# 야간순찰 시스템 가이드

플레이어 · 상호작용 · 점검 판정 · 층 진행 · 근무일지 시스템을 쓰는 방법입니다.

- 담당: 시스템 담당(양우성)
- 기준: `develop` 브랜치, 시스템 PR이 머지된 뒤. 머지 전에는 `woosung` 브랜치에만 있습니다. 바뀐 것은 6. 도구·테스트·문제 해결 → 변경 이력
- 시스템 코드를 고쳐야 할 것 같으면 먼저 말해 주세요. 대부분은 이벤트 구독이나 Inspector 설정으로 해결됩니다.
- 공용 씬·테스트 씬·공용 프리팹은 보기 전용입니다. 실험은 자기 `Assets/_Dev/이름/` 폴더로 복제해서 합니다.
- 이 메인과 아래 페이지 6개로 나뉩니다. 노션은 메인 아래 하위 페이지로, 레포 `Docs/시스템_가이드.md`는 같은 내용을 한 파일에 같은 순서로 담았습니다.

| 페이지 | 내용 |
| --- | --- |
| 1. 씬에 놓기 | 씬에 Player·PatrolSystems·엘리베이터 놓기, 테스트 씬 |
| 2. 점검 사물과 점검 항목 표 | 점검 사물 만들기, Id 규칙, 지금 있는 점검 사물, 사물 소리, 점검 항목 표(Id 패턴·자동 문구·예외 지시), Floor5 표 |

## 핵심 루프

```
층 도착 → 근무일지 확인(Tab) → 점검·조치(E) → 엘리베이터(E 길게)
   ├─ 점검 사물이 전부 정상 → 아래층 (마지막 층 도착 = 클리어)
   └─ 하나라도 비정상 → 실패: 회차 +1, 5층 시작 자리로
```

층은 같은 씬을 다시 씁니다. 층이 바뀌면 사물을 처음 상태로 되돌리고, 표지판·조명·이상현상만 바꿉니다 (기획서 4.2).

층이 시작될 때의 순서(초기화 → 이벤트 → 점검 항목)는 3. 층 진행과 이벤트에 있습니다.

## 자주 하는 실수

- `Assets/Fonts/*SDF.asset`, `LiberationSans SDF - Fallback.asset`은 Play하면 글자 아틀라스가 저장되어 변경으로 뜹니다. 커밋하지 말고 되돌립니다 (`git checkout -- 파일`).
- `ProjectSettings/`가 에디터 작업 중 저절로 바뀌는 경우가 있습니다. 의도한 변경이 아니면 커밋하지 않습니다.
- 씬은 동시에 편집하지 않습니다 (기획서 8.2). Floor5는 송지우님 담당
- 이상현상을 `Start()`에서 켜지 않기 → `FloorStarted`
- 생성된 오브젝트에 손으로 컴포넌트 붙이지 않기 → Id로 찾기
- 점검 사물의 처음 상태는 정상
- 손에 드는 물체는 `FirstPerson` 레이어, 콜라이더 없이
- ESC 메뉴가 열리면 `Time.timeScale = 0`, 소리 일시정지입니다. 이상현상·연출은 `Time.deltaTime`(기본)과 일반 AudioSource를 쓰면 메뉴 동안 같이 멈춥니다. 메뉴 중에도 움직여야 하는 것만 `unscaledDeltaTime`
- 에디터에서는 ESC 메뉴의 화면 모드·해상도를 바꿔도 Game 뷰가 안 바뀝니다 (빌드에서 적용, 메뉴에도 "(빌드에서 적용)"으로 표시)
- 되돌리기 어려운 조작은 `IHoldInteractable`로 길게 누르게
- 사물 소리를 AudioSource로 직접 내면 층이 시작될 때 한꺼번에 울립니다 → `SoundEmitter`
- 입력 액션을 직접 `Disable()`·`Clone()`하지 않기 → `KeyInput`
- 시스템 코드 수정이 필요하면 시스템 담당(양우성)에게 (PR 코멘트나 카톡)

# 1. 씬에 놓기

## 씬 구성 (빠른 시작)

| 놓을 것 | 방법 |
| --- | --- |
| 플레이어 | `Assets/Prefabs/Player.prefab`을 시작 자리(5층 경비 데스크)에 놓기. 카메라가 들어 있으니 씬의 다른 카메라·플레이어는 지우기 |
| 층 진행 | `Assets/Prefabs/PatrolSystems.prefab` 하나 놓기 (위치 상관없음). `PatrolRun` + `FloorTasks`가 들어 있고 Floor5용 표가 연결돼 있음. 씬에 하나만 |
| 엘리베이터 | 엘리베이터 버튼(또는 문) 오브젝트에 `Elevator` + 콜라이더. E를 0.7초 눌러야 내려감 (`Hold Seconds`, 0이면 한 번) |
| 점검 항목 표 | Floor5는 `Assets/Data/TaskTable_Floor5` (PatrolSystems에 연결됨). 새로 만들려면 Project 창 우클릭 → Create → Night Patrol → Task Table (2. 점검 사물과 점검 항목 표) |

- 참조 칸은 비워 두면 씬에서 알아서 찾습니다 (Player, FloorTasks, Elevator의 Run, 엘리베이터 문).
- Player 프리팹만 놓아도 이동·E·일지·ESC 메뉴·HUD·개발자 도구는 동작합니다. 층 이동 연출과 일지의 점검 사항은 층 진행까지 있어야 나옵니다.
- 실패하면 돌아올 자리를 따로 정하려면 `PatrolRun`의 Start Point에 빈 오브젝트를 넣습니다 (비우면 플레이어가 처음 서 있던 자리).
- 전부 들어간 예: 테스트 씬 `Test_04_03_Clipboard` (아래 "테스트 씬")
- 공용 씬(Floor5) 배치는 씬 담당(송지우님)이 합니다. 직접 해 보려면 공용 씬을 고치지 말고 자기 `Assets/_Dev/이름/`으로 복제해서 하세요.
- 다 놓은 뒤 메뉴 `Night Patrol → 씬 점검`으로 빠진 것이 없는지 확인합니다 (6. 도구·테스트·문제 해결 → 에디터 도구).

# 2. 점검 사물과 점검 항목 표

## 점검 사물 만들기 (`PatrolObject`)

**개념**

- 점검 사물은 정상/비정상 상태가 있는 물건입니다 (전등, 문, 창문, 블라인드, 모니터 등).
- 엘리베이터를 탈 때 씬에 켜져 있는 모든 점검 사물이 정상이어야 아래층으로 갑니다. 하나라도 비정상이면 실패입니다.
- 꺼진(비활성) 사물은 판정에서 빠집니다.

**상속할 때 구현할 것**

| 멤버 | 필수 | 설명 |
| --- | --- | --- |
| `IsNormal` | 필수 | 규정상 정상이면 true (예: 전등이 꺼져 있음, 문이 잠겨 있음) |
| `ResetToDefault()` | 필수 | 처음 상태로 되돌리기. 층이 시작될 때마다 불림. 처음 상태는 반드시 정상 |
| `Prompt` | 필수 | 조준했을 때 문구 (예: "E - 전등 끄기") |
| `Interact(who)` | 필수 | E를 눌렀을 때 동작 |
| `TrySetAbnormal()` | 선택 | 점검 항목으로 뽑혔을 때 비정상으로 바꾸고 true. 지원 안 하면 override하지 않음 (기본 false). 실패할 수 있는 준비(재질·셰이더 등)는 상태를 바꾸기 전에 |
| `Id` | Inspector | `구역.종류.번호` (예: `R21.Monitor.03`, `Corridor.Lamp.01`) |

**부모가 알아서 하는 것**

| 멤버 | 설명 |
| --- | --- |
| `IsClear` | 판정 기준. `IsNormal`이면서(예외 지시면 반대) 이상현상도 없음 |
| `IsException` | 이번 층 예외 지시 대상인지 (아래 "예외 지시"). 점검 항목 표가 정하고 층이 시작되면 풀림 |
| `HasAnomaly`, `AddAnomaly()`, `RemoveAnomaly()` | 이상현상 카운트 (4. 이상현상과 근무일지) |

**예시: 선풍기**

모니터·TV는 이미 송지우님 `MonitorDevice`가 있습니다. 아래는 새 사물을 만드는 모양만 보여 주는 예시입니다.

```csharp
using NightPatrol.Interaction;
using NightPatrol.Patrol;
using UnityEngine;

public class DeskFan : PatrolObject
{
    [SerializeField] private Transform blades;
    [SerializeField] private float degreesPerSecond = 720f;
    private bool isOn;

    public override bool IsNormal => !isOn;                      // 규정 제2조: 전자기기는 꺼져 있어야 정상
    public override string Prompt => isOn ? "E - 선풍기 끄기" : "E - 선풍기 켜기";

    private void Awake() => ResetToDefault();
    public override void ResetToDefault() => isOn = false;      // 처음 상태 = 정상
    public override void Interact(PlayerInteractor who) => isOn = !isOn;

    public override bool TrySetAbnormal()                        // 점검 항목으로 뽑히면 켜짐
    {
        isOn = true;
        return true;
    }

    private void Update()
    {
        if (isOn && blades != null) blades.Rotate(0f, 0f, degreesPerSecond * Time.deltaTime);
    }
}
```

**체크리스트**

- 처음 상태(`ResetToDefault`)가 정상인가? 아니면 일지에는 없는데 판정에 걸립니다 (층 시작 때 콘솔에 `[Run] 초기화 직후 비정상` 경고).
- `Awake`에서 `ResetToDefault()`를 부르는가?
- 조준할 수 있게 콜라이더가 있는가?
- `Id`가 비어 있지 않고 다른 사물과 겹치지 않는가?

## Id 규칙

- 형식: `구역.종류.번호` — 구역 `R21`(521호), `Corridor`, `StairW` 등 / 종류 `Door`, `Window`, `Blind`, `Lamp`, `Monitor` 등 / 번호 `01`부터
- 층 번호는 넣지 않습니다 (모든 층이 같은 씬).
- 맵 생성기(FloorGenerator)가 만든 문·창문·블라인드·모니터·TV는 Id가 자동으로 붙습니다 (생성 순서대로 번호). 손으로 놓은 사물은 직접 적습니다.
- 생성기가 만든 오브젝트에 손으로 컴포넌트를 붙이거나 직접 참조하면 Generate Floor를 다시 할 때 사라집니다. 다른 코드에서는 Id로 찾습니다: `PatrolInspection.FindById("R21.Door.01")`

## 지금 있는 점검 사물

| 클래스 | 담당 | 정상 | 점검 항목 지원 (`TrySetAbnormal`) |
| --- | --- | --- | --- |
| `PatrolLamp` | 시스템 담당 (예시) | 전등 꺼짐 | 있음 (켜짐) |
| `Door` | 송지우님 | 닫히고 잠김 | 있음 (잠금 해제 + 열림) |
| `WindowUnit` | 송지우님 | 닫히고 잠김 | 있음 (잠금 해제 + 열림) |
| `WindowBlind` | 송지우님 | 규정 쪽(보통 내려감) | 있음 (반대 상태) |
| `MonitorDevice` | 송지우님 | 꺼짐 (모니터 `R21.Monitor.01~`, 천장 TV `R24.TV.01~02`) | 있음 (켜 둠) |

`TrySetAbnormal`이 false를 돌려주면(예: 문짝·화면이 연결 안 됨) 그 사물은 점검 항목으로 뽑히지 않습니다.
실패했는데 상태가 이미 바뀌었거나 오류가 났으면, 시스템이 그 사물을 `ResetToDefault`로 되돌려 일지에 없는 비정상으로 남지 않게 합니다. 빌드에서만 나는 실패도 있으니(예: 이름으로 찾는 셰이더가 빌드에 없음) 재질·셰이더는 Inspector 칸으로 연결하세요.

## 판정·검색 도구 (`PatrolInspection`)

| 기능 | 설명 |
| --- | --- |
| `IsAllClear()` | 켜진 점검 사물이 전부 정상인지 (엘리베이터가 씀) |
| `FindAbnormal()` | 비정상 사물 목록 (Id 순). 매 프레임 부르지 않기 |
| `FindById(id)` | Id로 사물 찾기 (꺼진 것 포함). 없으면 null. 층 시작 때 만든 표를 써서 빠름 |
| `MapById()` | Id → 사물 표. 중복 Id는 경고 |

## 사물 소리 (`SoundEmitter`)

문·창문·모니터·엘리베이터·이상현상처럼 사물에서 나는 소리를 냅니다. 붙인 위치에서 방향과 거리에 따라 들립니다 (3D).

**붙이는 법**

1. 소리를 낼 오브젝트에 Add Component → `SoundEmitter`
2. Cues에 소리 묶음을 추가

| 칸 | 설명 |
| --- | --- |
| Name | 부를 때 쓰는 이름 (예: `열림`) |
| Clips | 소리 파일. 여러 개면 무작위로 고르고, 방금 낸 것은 바로 다시 고르지 않음 |
| Volume | 음량 (0~1). ESC 메뉴의 소리 크기와 곱해짐 |
| Pitch Jitter | 높낮이를 이만큼 무작위로 (0.05 = ±5%, 반복이 덜 거슬리게). 0이면 늘 원래 높이 (엘리베이터 "띵"처럼 늘 같아야 하는 소리) |
| Play On | 코드 없이 저절로 울릴 순간: `DescendStarted`(하행 시작) · `Arrived`(도착). 엘리베이터용, 보통은 `None` |
| Full Volume Distance / Silent Distance (묶음 아래) | 이 거리(m) 안은 원래 크기 (기본 1) / 이 거리부터 안 들림 (기본 20). 그 사이는 멀수록 작아짐 |

**코드에서 내기** (위 선풍기 예시에 소리를 붙이면)

```csharp
using NightPatrol.Audio;

[SerializeField] private SoundEmitter sound;   // 같은 오브젝트의 SoundEmitter. 비우면 소리 없음

public override void Interact(PlayerInteractor who)
{
    isOn = !isOn;
    if (sound != null) sound.Play(isOn ? "켜짐" : "꺼짐");
}
```

**규칙**

- 층이 시작되는 동안(사물 초기화 → 이벤트 → 점검 항목 만들기)과 씬을 막 불러온 순간에는 소리를 내지 않습니다. 그래서 상태가 바뀔 때마다 `Play`를 불러도, 층이 시작될 때 문 수십 개가 한꺼번에 울리지 않습니다. 층 도중에 바뀌면(플레이어 조작, 이상현상) 소리가 납니다.
- 없는 이름을 부르면 콘솔에 `[Sound] … 소리 묶음 '이름'이 없음` 경고가 이름마다 한 번 나옵니다. 파일이 빈 묶음은 조용합니다 (소리 파일을 아직 안 넣었을 때).
- 엘리베이터: 엘리베이터 오브젝트에 붙이고, 묶음 두 개의 Play On을 `DescendStarted`·`Arrived`로 고르면 코드 없이 울립니다. 문 여닫는 소리는 `ElevatorDoors` 쪽에서 `Play`를 부릅니다.
- 벽은 소리를 막지 않습니다 (거리만 계산). ESC 메뉴가 열리면 다른 소리처럼 멈춥니다.
- 플레이어 몸에서 나는 소리(발소리·E·일지·깨어나기)는 `PlayerSounds`가 방향 없이 냅니다 (5. 플레이어·조작 키·메뉴 → Player 프리팹).
- 다른 코드에서 "지금 층을 시작하는 중인지" 알려면 `PatrolRun.IsStartingFloor` (3. 층 진행과 이벤트)

## 점검 항목 표 (`TaskTable`)

**동작**

- 층이 시작될 때 표에서 2~3개를 뽑아, 각 항목의 대상 사물을 비정상으로 만들고 근무일지에 문구를 적습니다.
- 점검 항목은 "이번 층에 특별히 확인할 것"입니다. 규정(전자기기 꺼짐, 출입문 잠김)은 항상 적용되므로, 표에 없는 사물도 비정상이면 판정에 걸립니다.

**만드는 법**

1. Project 창 우클릭 → Create → Night Patrol → Task Table
2. Entries에 항목 추가

| 칸 | 설명 |
| --- | --- |
| Label | 일지에 적힐 문구. `{room}` = 고른 대상의 방 이름, `{floor}` = 지금 층 (예: `{room} 블라인드 내리기` → 5층에서 `524호 블라인드 내리기`). 비우면 대상 Id가 적힘 |
| Ids | 대상 사물 Id 또는 패턴 (아래 "Id 패턴"). 여러 개면 맞는 사물 중 하나만 비정상이 됨 |
| Exception | 예외 지시 (아래) |
| Area Names (표 아래) | `{room}`에 쓸 구역 이름 (아래 "자동 문구") |
| Room Floor (표 아래) | 방 번호의 층. 0 = 지금 층 (아래 "자동 문구") |

- 일지에는 표 순서대로 적힙니다. 권장 순찰 순서(형광등 켜고 개폐 확인 → 소등 → 손전등)대로 배치하세요 (기획서 3.6).
- 여러 사물을 하나로 묶을 때는 패턴이 편합니다. 예: Label `교수실 구역 잠금 확인`, Ids `R05~R19.Door.*` → 교수실 문 중 하나만 열림
- 대상 사물이 `TrySetAbnormal()`을 지원해야 뽑힙니다.

**표 연결** (`FloorTasks`, 보통 PatrolRun과 같은 오브젝트)

| 값 | 기본 | 설명 |
| --- | --- | --- |
| Table | — | 위에서 만든 표 |
| Min Tasks / Max Tasks | 2 / 3 | 층마다 뽑는 개수 |
| Seed | 0 | 0이면 매번 랜덤. 다른 숫자면 같은 층·회차에 항상 같은 항목 (테스트용) |

- 다른 코드에서 이번 층 항목이 필요하면 `FloorTasks.CurrentTasks`(각 항목의 `Label`, `Target`)와 `TasksChanged` 이벤트를 씁니다.
- 표와 씬 설정이 맞는지는 메뉴 `Night Patrol → 씬 점검`으로 확인합니다 (6. 도구·테스트·문제 해결 → 에디터 도구).
- 표를 고치는 동안에는 표 Inspector 아래 "미리보기 (열린 씬)"에서 줄마다 맞는 사물 수와 실제 문구를 바로 볼 수 있습니다 (6. 도구·테스트·문제 해결 → 에디터 도구).

## Id 패턴과 자동 문구

**Id 패턴**

Id를 점(.)으로 나눈 칸마다 비교합니다 (대소문자 구분). 패턴이 아니면 전처럼 정확히 같은 Id만 맞습니다.

| 쓰는 법 | 뜻 | 예 |
| --- | --- | --- |
| `*` | 그 칸의 아무 글자 | `R21.Monitor.*` (521호 모니터 전부), `Stair*.Door.*` (계단실 문) |
| `A~B` | 같은 접두어·같은 자릿수의 숫자 범위 | `R05~R19.Door.*` (R05~R19 문), `R24.Window.01~05` |

- 사물이 늘어도 패턴에 맞으면 표를 안 고쳐도 후보가 됩니다 (생성기로 다시 만들어도 Id 규칙만 같으면 됨).
- 패턴은 칸이 3개(구역.종류.번호)여야 합니다. 범위는 `R05~R19`처럼 양쪽 접두어·자릿수를 맞추고 앞 숫자가 작거나 같게 씁니다. `R5~R19`·`R19~R05` 같은 틀린 패턴은 아무것도 안 맞고, 콘솔에 이유가 나옵니다.
- 정확한 Id와 패턴이 같은 사물을 가리켜도 후보는 하나로 셉니다. 후보를 Id 순으로 정리한 뒤 섞으므로, Seed가 같으면 씬의 오브젝트 순서와 상관없이 같은 결과입니다.

**자동 문구** (`{room}`·`{floor}`)

- `{room}`은 고른 대상 Id의 첫 칸(구역)으로 정합니다.
  1. 표의 `Area Names`에 그 구역이 있으면 그 이름 (예: `StairW` → `서쪽 계단실`). 이름 안에 `{floor}`를 쓰면 지금 층. 같은 구역이 두 줄이면 첫 줄
  2. 없으면 방 번호(`R`+두 자리)는 층+번호+호 (5층 `R21` → `521호`, 4층 → `421호`)
  3. 그 밖의 구역은 코드 그대로 (예: `Corridor`)
- `Room Floor`: 0(기본)이면 방 번호를 지금 층으로 바꿉니다. 표지판이 층마다 안 바뀌면 5로 두어 항상 `521호`로 적습니다. `{floor}`는 Room Floor와 상관없이 늘 지금 층입니다.
- 한 층의 일지 문구는 서로 다릅니다. 고른 대상의 문구가 이미 뽑힌 항목과 같으면 그 대상은 건너뛰고 다른 대상을 고릅니다 (일지의 해결 표시가 문구로 짝짓기 때문). 건너뛴 사물은 비정상으로 만들지 않습니다.
- 모르는 자리표시(`{rom}` 같은 오타)는 글자 그대로 나옵니다. 씬 점검과 자동 테스트가 알려 줍니다.

## 예외 지시 (기획서 3.5 내용 판단형)

- 항목의 `Exception`을 체크하면, 뽑힌 대상이 비정상 상태(예: 켜짐)로 시작하고 그 층에서는 그 상태가 정상입니다.
- 예: Label `521호 강사 PC는 업데이트 중 — 끄지 말 것`, Ids `R21.PC.01`, Exception 체크 → 규정대로 다 끄고 다니면 실패, 일지를 읽고 켜 둬야 통과
- 일지에는 표시 방식과 상관없이 항상 `※ 문구`로 보이고, "점검 사항 N건"에는 세지 않습니다.
- 층이 바뀌면 예외는 풀립니다. 같은 사물이 예외와 일반 항목에 동시에 뽑히지 않습니다.
- 사물 클래스는 고칠 필요가 없습니다 (`TrySetAbnormal`만 있으면 됨).

# 3. 층 진행과 이벤트

## 층이 시작될 때 (항상 이 순서)

1. 모든 점검 사물을 처음 상태로 되돌림 (`ResetToDefault`). 이상현상 카운트·예외 지시도 초기화
2. `FloorReset(층)` 이벤트 — 점검 사물이 아닌데 층마다 처음 상태로 돌아가야 하는 것
3. `FloorStarted(층)` 이벤트 — 이상현상·표지판·조명 바꾸기
4. 점검 항목 표에서 2~3개를 뽑아 대상 사물을 비정상으로 만듦
5. 근무일지 갱신

> 3번에서 이상현상을 건 사물은 4번에서 점검 항목으로 뽑히지 않습니다 (정상인 사물만 뽑기 때문).

## 층 진행 설정과 값 (`PatrolRun`)

**Inspector**

| 값 | 기본 | 설명 |
| --- | --- | --- |
| Floors | 5, 4, 3, 2, 1 | 내려가는 층 순서. 마지막 층 도착 = 클리어. 최소 구성은 5, 3, 1 |
| Start Point | 비어 있음 | 실패하면 돌아오는 자리. 비우면 플레이어가 처음 서 있던 자리 |
| Player / Tasks | 자동 | 비워 두면 씬에서 찾음 |

**읽을 수 있는 값**

| 값 | 설명 |
| --- | --- |
| `CurrentFloor` | 지금 층 번호 |
| `Attempt` | 회차 (1부터, 실패할 때마다 +1) |
| `IsCleared` | 마지막 층에 도착했는지 |
| `FailedFloors` | 실패한 층 목록 (실패한 순서대로) |
| `IsFirstFloor` | 지금 첫 층(보통 5층)인지 |
| `LastStart` | 이번 층이 시작된 이유: `GameStart` · `Descend`(하행 성공) · `Fail` · `Restart`(F4) · `Jump`(PgUp/PgDn) |
| `IsStartingFloor` | 층을 시작하는 중인지 (사물 초기화부터 점검 항목 만들기까지). 이 동안 `SoundEmitter`는 조용 |

- `PatrolRun.Current` (static): 씬의 층 진행 (없으면 null). Start 이후·이벤트 안·Update에서 바로 씁니다. 예: `var run = PatrolRun.Current; if (run != null && run.CurrentFloor == 3) { ... }`
- Awake·OnEnable에서는 PatrolRun보다 먼저 깨어나면 아직 null입니다. 이벤트를 구독할 때는 아래 예시처럼 `FindAnyObjectByType<PatrolRun>()`으로 찾으세요.
- PatrolRun이 둘이면 먼저 켜진 쪽이고, 그 쪽이 꺼지면 다른 쪽이 켜져 있어도 null입니다. 씬에는 하나만 둡니다 (씬 점검이 알려 줌).

## 이벤트 (팀원 코드는 이걸 구독)

| 이벤트 | 언제 | 쓰는 곳 예시 |
| --- | --- | --- |
| `FloorReset(int 층)` | 층이 시작될 때 맨 먼저: 점검 사물 초기화 직후, `FloorStarted` 전 | 점검 사물이 아닌데 층마다 처음 상태로 돌아가야 하는 것. 이상현상은 여기서 켜지 않기 |
| `FloorStarted(int 층)` | `FloorReset` 다음, 점검 항목 생성 전 (게임 시작, 하행, 실패 후 5층) | 이상현상 켜기, 표지판 숫자 |
| `Failed(int 실패한 층)` | 실패했을 때. 바로 다음에 5층 `FloorStarted`가 옴 | 실패 연출, 소리 |
| `Cleared()` | 마지막 층(1층)에 도착 | 이상현상 끄기, 엔딩 |

- 구독한 코드에서 오류가 나도 콘솔에 빨갛게 뜰 뿐 게임은 계속 진행됩니다 (다른 구독자와 점검 항목 생성도 그대로). 이 문서에 나오는 시스템 이벤트는 모두 같습니다.
- 팀원 사물의 이벤트(`Door`·`WindowUnit`·`WindowBlind`·`MonitorDevice`의 `StateChanged`, `ElevatorDoors`의 `Opened`·`Closed`, `LightZone.Changed`, `Flashlight.Toggled`)는 위와 달리 구독자 오류가 그대로 전파됩니다 (예: 문 소리 구독자 오류 → 잠금만 풀리고 문은 안 열림). 구독하는 쪽에서 오류가 나지 않게 하세요. 층이 시작될 때 사물 초기화(`SetStateImmediate`)에서도 `StateChanged`가 오므로, 소리는 `SoundEmitter`로 내면 층이 시작되는 동안 저절로 조용합니다 (2. 점검 사물과 점검 항목 표 → 사물 소리).
- 1층 도착(`Cleared`)에는 `FloorStarted`가 오지 않습니다.
- 개발자 키 F4(층 재시작)·PgUp/PgDn(층 이동)으로도 `FloorReset`·`FloorStarted`가 옵니다. 이유를 구분하려면 `LastStart`를 봅니다.
- 사물 하나의 코드 오류(`ResetToDefault`·`TrySetAbnormal`·`IsNormal`의 예외)는 그 사물만 건너뛰고 층 시작은 끝까지 갑니다. `IsNormal`에서 오류가 나는 사물은 비정상으로 셉니다 (오류 로그는 층마다 한 번).
- `TrySetAbnormal`에 실패한 점검 후보는 기본 상태로 되돌리고 같은 줄의 다른 후보를 고릅니다. 같은 줄에서 오류가 여러 번 나면 층마다 첫 오류만 자세히 남고 나머지는 개수로 나옵니다.

```csharp
using NightPatrol.Run;
using TMPro;
using UnityEngine;

// 예: 층이 바뀌면 호수 표지판 앞자리를 바꿈 (521 → 421)
public class RoomSign : MonoBehaviour
{
    [SerializeField] private TMP_Text label;
    [SerializeField] private string roomNumber = "21";
    private PatrolRun run;

    private void Awake() => run = FindAnyObjectByType<PatrolRun>();
    private void OnEnable() { if (run != null) run.FloorStarted += OnFloorStarted; }
    private void OnDisable() { if (run != null) run.FloorStarted -= OnFloorStarted; }

    private void OnFloorStarted(int floor)
    {
        label.text = $"{floor}{roomNumber}";
        // 하행 성공으로 온 층에서만 하고 싶으면: if (run.LastStart == FloorStartReason.Descend) { ... }
    }
}
```

## 층 이동 연출 (`FloorTransition`, Player 프리팹 HUD)

엘리베이터 E → 조작 잠금 → 엘리베이터 문 닫힘 → 화면 어두워짐 → 어두운 동안 판정·층 바꾸기 → "N층" → 밝아짐 → 문 열림 → 잠금 해제

실패하면 어두운 동안 시작 자리로 옮겨진 뒤, 깜빡이며 고개를 드는 "졸다 깨는" 연출이 나옵니다 (개발자 키 F3도 같음). 게임 시작 때는 검은 화면에서 밝아집니다.

- 엘리베이터 문은 송지우님의 `ElevatorDoors`(Elevator_Base 프리팹 루트, 문짝 `Door_Left`·`Door_Right`, 층 표시)를 씁니다. 문이 끝까지 안 움직여도 `Move Seconds` + 0.5초 뒤에는 연출이 계속되고, 문이 없거나 꺼져 있으면 문 연출만 빠집니다.
- 엘리베이터 층 표시는 `ElevatorDoors`가 `FloorStarted`를 구독해 바꿉니다. 1층 도착(클리어)에는 `FloorStarted`가 오지 않으므로, 그때도 표시를 바꾸려면 `Cleared`를 같이 구독합니다.

| 이벤트 | 언제 | 예시 |
| --- | --- | --- |
| `DescendStarted` | 하행 연출 시작 | 버튼음, 문 닫히는 소리 |
| `Arrived(int 층)` | 하행 성공, "N층"을 띄우기 직전 | "띵" 소리 |
| `WakeStarted` | 졸다 깨는 연출 시작 | 숨 들이쉬는 소리 |

- 엘리베이터 소리만 낼 거면 코드 없이 엘리베이터의 `SoundEmitter`에서 Play On을 고르면 됩니다 (2. 점검 사물과 점검 항목 표 → 사물 소리). 아래 예시는 이벤트를 직접 구독하는 방법입니다.

```csharp
using NightPatrol.Run;
using UnityEngine;

// 예: 엘리베이터 도착음
public class ElevatorDing : MonoBehaviour
{
    [SerializeField] private AudioSource ding;
    private FloorTransition transition;

    private void Awake() => transition = FindAnyObjectByType<FloorTransition>();
    private void OnEnable() { if (transition != null) transition.Arrived += OnArrived; }
    private void OnDisable() { if (transition != null) transition.Arrived -= OnArrived; }

    private void OnArrived(int floor) => ding.Play();
}
```

- 연출 중에는 이동·시점·E·일지(Tab)가 모두 잠기고, 들고 있던 일지는 내려갑니다. 엘리베이터 문구도 사라지고 다시 눌리지 않습니다.
- 연출 중에 오류가 나도 연출은 끝까지 가고 잠금이 풀립니다.
- `FloorTransition`을 끄면 엘리베이터는 연출 없이 바로 하행합니다.

# 4. 이상현상과 근무일지

## 이상현상 연결 규칙

1. 이상현상은 `FloorStarted`에서 켭니다. `Start()`에서 켜면 층 시작 초기화와 순서가 꼬여 카운트가 지워지거나 점검 항목과 겹칩니다.
2. 이상이 걸린 동안 대상 사물에 `AddAnomaly()`를 해 두면, 사물이 정상이어도 판정에 걸립니다. 해결되면 `RemoveAnomaly()`
3. 층이 시작될 때 이상 카운트는 시스템이 0으로 만듭니다. 그래서 `FloorStarted`에서는 이전 층 이상의 겉모습만 되돌리고 `RemoveAnomaly()`는 부르지 않습니다 — 다른 이상현상이 이번 층에 같은 사물에 건 카운트까지 지워집니다. `RemoveAnomaly()`는 층 도중에 해결됐을 때, `Cleared`, 꺼질 때(`OnDisable`)에 부릅니다.
4. 대상은 Id로 찾습니다: `PatrolInspection.FindById("R21.Monitor.03")`. 생성된 오브젝트에 직접 붙이거나 참조하지 않습니다 (Generate Floor 때 사라짐).
5. 첫 회차 5층(`run.Attempt == 1 && floor == 5`)은 이상현상 없이 점검 항목만 있습니다 (기획서 3.4).
6. 1층 도착(`Cleared`)에는 `FloorStarted`가 오지 않으니 `Cleared`에서도 끕니다.
7. 점검 항목은 `FloorStarted` 다음에 정상인 사물 중에서 뽑히므로, 이상 대상과 겹치지 않습니다.
8. 모니터·TV 화면은 재질을 직접 바꾸지 말고 `MonitorDevice.OverrideScreen(재질)` / `ClearScreenOverride()`를 씁니다 (켜고 끌 때 덮어써지지 않게).

## 이상현상 예시

```csharp
using NightPatrol;          // MonitorDevice (송지우님)
using NightPatrol.Patrol;
using NightPatrol.Run;
using UnityEngine;

public class MonitorAnomalyManager : MonoBehaviour
{
    [SerializeField] private string[] targetIds = { "R21.Monitor.03", "R21.Monitor.07" };
    [SerializeField] private Material anomalyScreen;
    private PatrolRun run;
    private PatrolObject current;

    private void Awake() => run = FindAnyObjectByType<PatrolRun>();
    private void OnEnable()
    {
        if (run == null) return;
        run.FloorStarted += OnFloorStarted;
        run.Cleared += OnCleared;
    }
    private void OnDisable()
    {
        if (run != null)
        {
            run.FloorStarted -= OnFloorStarted;
            run.Cleared -= OnCleared;
        }
        TurnOff(true);   // 꺼질 때는 걸어 둔 이상까지 푼다
    }

    private void OnFloorStarted(int floor)
    {
        TurnOff(false);   // 카운트는 시스템이 이미 0으로 만들었다 — 겉모습만 되돌림 (규칙 3)
        if (run.Attempt == 1 && floor == 5) return;      // 첫 회차 5층은 이상 없음
        current = PatrolInspection.FindById(targetIds[Random.Range(0, targetIds.Length)]);
        if (current == null) return;
        if (current is MonitorDevice monitor) monitor.OverrideScreen(anomalyScreen);   // 규칙 8
        current.AddAnomaly();
    }

    private void OnCleared() => TurnOff(true);

    // 플레이어가 층 도중에 해결했을 때(예: 전화 안내 → 스위치)도 TurnOff(true)
    private void TurnOff(bool removeCount)
    {
        if (current == null) return;
        if (current is MonitorDevice monitor) monitor.ClearScreenOverride();
        if (removeCount) current.RemoveAnomaly();
        current = null;
    }
}
```

## 형태별 힌트 (기획서 3.8)

| 형태 | 방법 |
| --- | --- |
| 꺼지지 않음 | `AddAnomaly()` + 화면을 계속 켠 모습으로. 해결(전화 안내 → 스위치) 시 `RemoveAnomaly()` |
| 되돌아옴 | `Update`에서 대상의 `IsNormal`을 보다가, 플레이어가 끄면(정상이 되면) 잠시 뒤 `TrySetAbnormal()`로 다시 켬 |
| 지시가 이상함 | 일지 수정자(아래 "일지 바꾸기")로 건수·줄을 바꾸거나, 점검 항목이 아닌 사물에 `AddAnomaly()` → 일지와 실제가 어긋남 |
| 상태가 어긋남 | 빨간 전등 등 점검 사물을 비정상(켜짐)으로. 플레이어가 끄면 해결 |

## 근무일지 (클립보드)

- Tab으로 눈앞에 들고 내립니다. 든 동안은 E 조작이 막힙니다 (`Clipboard`의 `JournalHolder` → Block Interaction While Raised를 끄면 들고도 조작 가능).
- 층 이동 연출 중에는 Tab이 먹지 않고, 들고 있던 일지는 내려갑니다.
- ESC 메뉴는 같은 클립보드에 메뉴 장을 보여 줍니다. 메뉴가 열린 동안 Tab은 무시되고, 닫으면 원래 일지로 돌아갑니다.
- 표시 순서: 지난 순찰 기록(켜져 있으면) → 야간 순찰 규정 → 점검 사항. 1층 도착 시 `점검 완료. 퇴근하십시오.`
- 규정 문구: Player 프리팹 → `JournalCanvas`의 `JournalView` → Rules
- 한글은 Noto Sans KR이 TMP 기본 Fallback으로 등록되어 있어서 따로 설정할 필요가 없습니다.

**다른 코드에서**

- `JournalHolder`: `IsRaised`, `RaisedChanged` 이벤트, `SetRaised(bool)`, `SetBlocked(this, bool)`, `SetMenuOpen(bool)`
- `JournalView`: `Refresh()`, `AddModifier`·`RemoveModifier`

## 일지 표시 설정 (`JournalView`)

모두 Player 프리팹 → `JournalCanvas`의 `JournalView` Inspector에서 바꿉니다.

**층별 정보량** (기획서 3.4) — `JournalView` → Displays

| 층 | 지금 설정 | 일지 |
| --- | --- | --- |
| 5, 4 | List | 점검 사항 목록 |
| 3, 2 | Count | "점검 사항 N건" |
| 1 | — | "점검 완료. 퇴근하십시오." |

- 고를 수 있는 방식: `List`(목록) · `Count`("N건") · `Unknown`("?건") · `AtMost`("N건 이하", N = FloorTasks의 Max Tasks)
- 재미 검증 결과에 따라 Inspector에서 바로 바꿀 수 있습니다.

**해결한 점검 사항 표시** — `JournalView` → Reveal, Strike Solved

| 칸 | 지금 설정 | 뜻 |
| --- | --- | --- |
| Reveal | When Solved | "N건"·"?건"만 보이는 층에서 항목을 목록에 드러냄. `Off` 안 함 / `When Solved` 해결하면 / `When Aimed` 대상을 조준하면 |
| Strike Solved | 켬 | 해결한 줄에 중간선 |

**지난 순찰 기록** (기획서 3.3) — `JournalView` → Failure Record

- 실패한 층만 적습니다 (무엇을 놓쳤는지는 안 알려 줌). 최근 3회까지, 그 전은 "그 전 N회 생략"

```
■ 지난 순찰
· 4층 실패
· 3층 실패
```

- `Off`(지금 설정) / `FirstFloor`: 첫 층(일지 첫 장)에서만 / `EveryFloor`: 모든 층

## 일지 바꾸기 (`IJournalModifier`)

이상현상이 근무일지 내용을 바꿔야 할 때(기획서 3.8 "지시가 이상함" 등) 일지 코드를 고치지 않고 수정자를 등록합니다. 일지가 갱신될 때마다 `JournalPage`(한 장의 내용)를 받아 고치면 됩니다.

- 주의: 점검 사항 문구(`page.Tasks`)를 바꾸면 해결 표시(중간선·드러남)는 원래 문구로 짝지어서 어긋납니다. 문구는 그대로 두고 줄을 더하는 쪽으로 쓰세요.

```csharp
using NightPatrol.Journal;
using UnityEngine;

public class WrongCountAnomaly : MonoBehaviour, IJournalModifier
{
    private JournalView journal;

    private void Awake() => journal = FindAnyObjectByType<JournalView>();
    public void Activate() => journal.AddModifier(this);      // FloorStarted에서
    public void Deactivate() => journal.RemoveModifier(this);
    private void OnDisable() { if (journal != null) journal.RemoveModifier(this); }

    public void ModifyJournal(JournalPage page)
    {
        if (page.Display == TaskDisplay.List && page.Tasks.Count > 0)
            page.Tasks.RemoveAt(page.Tasks.Count - 1);          // 목록에서 한 줄이 빠짐
        else
            page.CountOverride = page.Tasks.Count + 1;          // "N건"이 실제와 다름
    }
}
```

| `JournalPage`에서 바꿀 수 있는 것 | 예 |
| --- | --- |
| `Title` | 제목 바꾸기 |
| `Notes` (맨 위 메모) | 메모 덩어리 추가 |
| `Rules` | 규정 문구 바꾸기 (`<color=#8a0000>…</color>` 같은 TMP 리치 텍스트 가능) |
| `Tasks` | 점검 사항 줄 빼기·더하기·바꾸기 (처리할 것, "N건"이 세는 것) |
| `Exceptions` | 예외 지시 줄 (`※`로 항상 보임) |
| `Display`, `CountOverride` | 표시 방식, "N건"의 숫자 |
| `ClearedText` | 1층 완료 글 (기획서 4.3 "확신을 준 뒤 배신") |

- 등록 순서대로 적용됩니다. 한 수정자에서 오류가 나도 콘솔에 뜨고 나머지는 적용됩니다.
- 끌 때 꼭 `RemoveModifier`로 해제합니다. 오브젝트가 파괴되면 자동으로 빠지지만, 컴포넌트를 끄기만 하면 계속 적용됩니다.

# 5. 플레이어·조작 키·메뉴

## 조작과 ESC 메뉴

| 키 | 동작 |
| --- | --- |
| WASD / 방향키 | 이동 (WASD는 조작 키에서 변경 가능, 방향키는 고정 보조) |
| 마우스 | 시점 |
| E | 바라보는 대상과 상호작용. 엘리베이터는 길게(0.7초) |
| Tab | 근무일지 들기 / 내리기 |
| F | 손전등 켜기 / 끄기 |
| ESC | 일시정지 메뉴 (클립보드) |
| F1~F5, PgUp/PgDn | 개발자 도구 (6. 도구·테스트·문제 해결) |

**ESC 메뉴**

- 첫 장: 계속하기 · 설정 · 처음으로 · 게임 종료
- 설정 장: 마우스 감도 · 소리 크기 · 화면 모드 · 해상도 · 프레임 제한 · 조작 키 · 뒤로
- 마우스: 줄에 올리면 선택, 클릭하면 실행, ◀ ▶ 클릭으로 값 조절, 휠로 선택 이동
- 키보드: W/S·↑↓ 선택, A/D·←→ 조절, E·Enter·Space 확인, ESC 닫기 (안쪽 장에서는 뒤로)
- 처음으로·게임 종료는 한 번 더 눌러야 실행됩니다. 처음으로 = 지금 씬을 다시 불러 5층 1회차부터

## 조작 키

**조작 키 바꾸기** (ESC → 설정 → 조작 키)

- 바꿀 수 있는 키: 앞으로·뒤로·왼쪽·오른쪽(WASD), 상호작용(E), 근무일지(Tab), 손전등(F)
- 고정: ESC(메뉴·취소), 마우스 시점, 메뉴 조작 키, 개발자 키
- 줄을 고르면 "키를 누르세요" → 다음에 누른 키(키보드, 마우스 오른쪽·가운데·옆 버튼)로 바뀝니다. ESC는 취소
- 다른 줄과 겹치면 두 줄의 키를 서로 바꿉니다. "기본값으로"는 전부 되돌림
- 바꾼 키와 설정(감도·소리·프레임 제한)은 PC에 저장되고(PlayerPrefs), 씬을 불러올 때마다 적용됩니다 — ESC 메뉴가 없는 씬에서도
- 사물 문구(`Prompt`)가 `E - …`로 시작하면 화면에는 E 자리에 지금 상호작용 키가 보입니다. 사물 코드는 `"E - 문 닫기"`처럼 쓰면 됩니다.

**지금 쓰는 키와 배정 원칙**

- 지금 쓰는 키: WASD·마우스, E(상호작용), Tab(근무일지), F(손전등), ESC(메뉴), F1~F5·PgUp/PgDn(개발자)
- 먼저 쓰기 시작한 사람의 키를 유지하고, 새 동작은 이미 쓰는 키를 피해서 고릅니다. 기본 키끼리 겹치면 자동 테스트가 실패합니다.

**새 키 동작 추가하기**

1. `Assets/InputSystem_Actions` → Player 맵에 액션 추가, 기본 키 바인딩 (Keyboard&Mouse 그룹)
2. `Assets/Settings/KeyBindingList.asset`에 줄 추가: 표시 이름 + 그 액션 (+ 합성 파트: Move의 up/down/left/right, 단일 키면 비움). 빠뜨리면 자동 테스트 `KeyBindingRulesTests`가 실패해서 알려 줍니다
3. 코드에서는 `KeyInput` 칸 하나로 읽습니다. Inspector의 Action 칸에 그 액션을 연결하고, 비워 두면 Fallback 키로 동작합니다

```csharp
using NightPatrol.Controls;
using NightPatrol.Player;
using UnityEngine.InputSystem;

[SerializeField] private KeyInput radioKey = new KeyInput(Key.Q);   // 액션을 연결하면 설정에서 바꾼 키, 비면 Q

private void Update()
{
    if (!PlayerControl.CanAct) return;          // ESC 메뉴·층 이동 연출·창 밖에서는 false
    if (radioKey.WasPressed()) ToggleRadio();   // IsPressed() · WasReleased() · KeyName(화면 표시용)도 있음
}
```

> 입력 에셋의 액션은 여러 곳이 같이 씁니다. 직접 `Disable()`하거나 `Clone()`하지 마세요 — 설정에서 바꾼 키가 안 먹거나 다른 기능이 멈춥니다.

- 메뉴에는 10줄까지 나옵니다 (지금 7줄).
- 목록 파일을 옮길 때는 Unity Project 창에서 끌어서 옮깁니다 (탐색기로 옮기면 GUID가 바뀌어 메뉴 연결이 끊김).

## 상호작용 (E)

**동작 방식**

- 화면 가운데에서 앞으로 레이를 쏴서 2m(Interaction Distance) 안의 첫 콜라이더를 찾습니다. 못 맞히면 반지름 5cm(Aim Assist Radius)로 한 번 더 찾아서 작은 스위치·잠금장치도 잡힙니다. 벽이 먼저 닿으면 그 뒤는 안 봅니다.
- 맞은 콜라이더나 그 부모에 `IInteractable`이 있으면 대상이 됩니다. 그래서 대상(또는 자식)에 콜라이더가 꼭 있어야 합니다.
- Trigger 콜라이더와 `Ignore Raycast` 레이어는 무시합니다. 컴포넌트가 꺼져 있으면 대상이 아닙니다.
- E는 누르는 순간 반응합니다.
- 조작할 수 있는 대상을 보면 화면 가운데 아래에 그 대상의 `Prompt` 문구가 뜹니다. 문구가 빈 문자열이면 조작할 게 없는 것으로 보고 조준점만 흐리게 남습니다.
- 일지를 든 동안·ESC 메뉴 동안은 조준점과 문구가 숨습니다.

**E로 누르는 물건 만들기**

점검 대상이 아닌 물건(스위치, 전화 등)은 `IInteractable`만 구현하면 됩니다.

```csharp
using NightPatrol.Interaction;
using UnityEngine;

public class BreakerSwitch : MonoBehaviour, IInteractable
{
    public string Prompt => "E - 차단기 내리기";   // 조준하면 보일 문구 (빈 문자열이면 안 보임)

    public void Interact(PlayerInteractor who)
    {
        Debug.Log("차단기 내림");
    }
}
```

**길게 눌러야 하는 물건**

되돌리기 어려운 조작(한 번 누르면 실패·진행이 바뀌는 것)은 E를 길게 누르게 합니다. `IInteractable` 대신 `IHoldInteractable`을 구현하고 `HoldSeconds`를 추가합니다.

```csharp
public class MainBreakerLever : MonoBehaviour, IHoldInteractable
{
    public string Prompt => "E 길게 - 메인 차단기 내리기";
    public float HoldSeconds => 1f;               // 1초 눌러야 실행
    public void Interact(PlayerInteractor who) => Debug.Log("메인 차단기 내림");
}
```

- 예시 클래스 이름은 프로젝트에 이미 있는 이름과 겹치지 않게 짓습니다 (위 두 예시도 이름이 다름).

- 누르는 동안 조준점 둘레 링이 차고, 떼거나 다른 곳을 보면 처음부터 다시입니다. 엘리베이터가 0.7초
- `Prompt`가 빈 문자열이면 링도 안 보입니다.

> 점검 대상(정상/비정상이 있는 것)이면 `IInteractable` 대신 `PatrolObject`를 상속합니다 (2. 점검 사물과 점검 항목 표).

## 조작 잠금 (`PlayerControl`)

연출·UI 동안 플레이어를 멈출 때 씁니다. "누가 잠갔는지"별로 관리해서, 여러 곳이 동시에 잠가도 각자 자기 것만 풀어 꼬이지 않습니다.

```csharp
using NightPatrol.Player;

var player = PlayerControl.Current;          // 씬의 플레이어 (없으면 null)
if (player != null) player.Lock(this, true); // 이동·시점·E·일지 잠금
// ... 연출이 끝나면
if (player != null) player.Lock(this, false);
```

- 일지는 빼고 잠그려면 `Lock(this, true, includeJournal: false)`. 잠글 때와 풀 때 같은 값으로
- 잠근 쪽이 꺼지거나 사라질 때(`OnDisable`) 꼭 `false`로 풀어 주세요. 안 풀면 계속 잠겨 있습니다.
- `PlayerControl.CanAct` (static): 지금 게임 키를 받아도 되는지. ESC 메뉴(시간 정지)·층 이동 연출(잠금)·커서가 풀림·창 밖이면 false, 일지를 든 동안은 true
- 지금 누가 잠갔는지는 F1 "자세히" 패널의 "조작 잠금" 구역에 보입니다.

| `PlayerLook` | `SetPitch(각도)` | 위아래 시선을 직접 정함 (+ 아래 / − 위, 연출용) |
| `PlayerInteractor` | `CurrentTarget`, `TargetChanged` | 지금 조준 중인 대상, 바뀔 때 이벤트 |
| `PlayerInteractor` | `Interacted` | E로 무언가를 조작한 직후 이벤트 (조작 소리, 이상현상 반응 등) |
| `PlayerInteractor` | `HoldProgress` | E 길게 누르기 진행도 (0~1) |
| `PlayerInteractor` | `InteractAction` | 상호작용 입력 액션 (지금 키 이름 표시 등) |
| `KeyBindings` | `KeyName(액션, 바인딩 번호)`, `Changed` | 지금 키 이름 ("W", "Tab", "마우스 오른쪽"), 키를 바꿨을 때 이벤트 |
| `JournalHolder` | `SetMenuOpen(bool)`, `IsMenuOpen` | 일지 상태와 따로 클립보드를 들어 올림 (ESC 메뉴가 씀) |

# 6. 도구·테스트·문제 해결

## 개발자 키와 F1 패널 (에디터·개발 빌드에서만)

| 키 | 동작 |
| --- | --- |
| F1 | 개발자 정보 표시. 누를 때마다 끔 → 간단(한 줄: 층·회차·이 층 시간·FPS) → 자세히(패널) → 끔 |
| F2 | 판정 무시하고 하행 |
| F3 | 강제 실패 |
| F4 | 지금 층 다시 시작 (사물 초기화 + 항목 다시 뽑기) |
| F5 | 기록 폴더 열기 (게임 로그 `logs/`, 플레이테스트 기록 `playtest/`) |
| PgUp / PgDn | 위층 / 아래층 이동 (맨 위·맨 아래에서는 무반응) |

- F2~F5·PgUp/PgDn은 F1 표시를 켠 동안에만 동작합니다 (플레이테스트 때 실수로 누르지 않게). 키 안내는 F1 "자세히" 패널 맨 아래에 있습니다.
- 층 이동 연출 중과 ESC 메뉴가 열린 동안에는 F2~F4·PgUp/PgDn을 무시합니다 (F5는 동작).
- 일반 빌드에서는 전부 동작하지 않습니다.
- "자세히" 패널 구역: 진행 · 점검 항목(처리됨 초록 ● / 남음 빨강 ○ / 예외 노랑) · 비정상 사물 · 조준 대상(이름·거리·문구·상태) · 조작 잠금 · (다른 코드가 붙인 구역) · 개발자 키

**F1 패널에 내 구역 추가** (`DevInfo`)

이상현상 상태처럼 개발 중에 보고 싶은 정보는 시스템 코드를 고치지 않고 구역으로 붙입니다.

```csharp
using NightPatrol.Debugging;
using UnityEngine;

// 예: 지금 켜진 이상현상을 F1 패널에 보이기
public class AnomalyDebugInfo : MonoBehaviour
{
    private string current = "없음";

    private void OnEnable() => DevInfo.Register(this, "이상현상", () => current);
    private void OnDisable() => DevInfo.Unregister(this);

    public void Show(string anomaly) => current = anomaly;   // 이상현상을 켤 때 불러 줌
}
```

- 글을 만드는 함수는 초당 4번만 불리고, 오류가 나도 패널에 빨간 글로 뜰 뿐입니다. 일반 빌드에서는 불러도 아무 일도 안 합니다.
- 순서는 `order`로 정합니다 (기본 100): 진행 0, 점검 항목 10, 비정상 20, 조준 30, 조작 잠금 40, 개발자 키 200
- 색은 `DevInfo.Paint(글, DevInfo.BadColor)` 같은 리치 텍스트로

## 에디터 도구 (빌드에 안 들어감)

메뉴 `Night Patrol`과 점검 항목 표 Inspector에 있는 에디터 전용 도구입니다.

**씬 점검** (메뉴 `Night Patrol → 씬 점검`)

열린 씬을 읽기만 하고 문제를 한 줄씩 보여 줍니다. 줄을 누르면 그 오브젝트가 선택됩니다. 씬·에셋은 바꾸지 않습니다.

- 플레이어·PatrolRun·FloorTasks·엘리베이터 버튼이 하나씩 있는지, FloorTasks에 표가 연결됐는지
- 엘리베이터 버튼에 E로 누를 콜라이더가 있는지 (트리거·Ignore Raycast 레이어는 안 됨)
- MainCamera 태그 카메라·AudioListener가 둘 이상 켜져 있는지
- 점검 사물의 빈 Id·중복 Id (꺼진 사물도 셈)
- 점검 항목 표: 패턴 오류, 씬에 없는 Id, 모두 꺼진 대상, 대상이 없는 줄, 같은 고정 문구, 구역 이름 중복·잘못된 자리표시
- 프리팹 편집 화면에서는 점검하지 않습니다. 씬으로 돌아가서 "다시 점검"

**점검 항목 표 미리보기** (표 Inspector 아래)

Project 창에서 점검 항목 표를 고르면 Inspector 맨 아래 "미리보기 (열린 씬)"에 줄마다 이렇게 나옵니다.

```
7. {room} 블라인드 내리기 — 맞는 사물 5개 (켜진 후보 5개) · 예: 524호 블라인드 내리기
```

- 열린(활성) 씬의 점검 사물에 층 시작과 같은 규칙으로 맞춰 보기만 합니다. 사물·씬·표는 바뀌지 않습니다.
- "미리보기 층"을 바꾸면 그 층의 문구로 보입니다 (`{room}`·`{floor}`, Room Floor 반영).
- 맞는 사물이 없거나 모두 꺼졌거나 패턴이 틀린 줄은 경고가 붙습니다. 같은 고정 문구·구역 이름 문제는 맨 아래에 나옵니다.
- 줄을 누르면 예시 대상을 Hierarchy에서 깜빡여 보여 줍니다 (선택은 그대로).
- 표를 쓰는 씬(예: Floor5)을 열어 두고 봐야 숫자가 맞습니다. 씬을 고치면 잠시 뒤 다시 읽고, 바로 보려면 "다시 읽기"를 누릅니다.
- 칸 모양은 기본 Inspector 그대로입니다. 프리팹 편집 화면에서는 미리보기를 하지 않습니다.

**점검 사물 목록** (메뉴 `Night Patrol → 점검 사물 목록`)

열린 씬의 점검 사물을 Id 순으로 보여 줍니다: Id · 종류 · 상태 (정상 / 비정상 / 예외 지시 → 통과·걸림 / 이상현상 → 걸림 / 꺼짐 / 오류).

- 줄을 누르면 그 사물이 선택됩니다. 검색 칸은 Id·종류로 거르고, "문제만"은 엘리베이터를 타면 걸리는 사물과 오류만 보여 줍니다.
- Play 중에는 상태가 0.5초마다 바뀌어 보이고, 줄마다 버튼 두 개가 나옵니다.
  - 기본 상태로: 그 사물의 `ResetToDefault`. 예외 지시·이상현상은 지우지 않고 점검 항목도 그대로입니다 (층 재시작 F4와 다름).
  - 비정상 만들기: 그 사물의 `TrySetAbnormal`. 지원하지 않는 사물은 그대로이고 창에 알림이 뜹니다.
- 편집 중에는 씬에 저장된 상태 그대로 보입니다 (Play를 시작하면 층 시작 때 기본 상태로 바뀜). 씬·에셋은 바꾸지 않습니다.
- 사물 코드에서 상태를 읽다가 오류가 나면 그 줄만 "오류: …"로 보이고 나머지는 그대로입니다.
- 왼쪽 점 색은 아래 "점검 상태 표시"와 같습니다.

**점검 상태 표시** (메뉴 `Night Patrol → 점검 상태 표시`, Scene 뷰)

기본은 꺼져 있습니다. 메뉴를 누르면 켜지고(체크 표시) 다시 누르면 꺼집니다. 켠 상태는 내 PC에만 저장됩니다.

- Scene 뷰에서 점검 사물마다 색 점이 찍힙니다: 초록 정상 / 빨강 비정상 / 노랑 예외 지시·이상현상 / 회색 꺼짐 / 자홍 오류.
- 정상이 아닌 사물에는 Id와 상태 글이 같이 나옵니다.
- Play 중에는 0.5초마다 바뀝니다. 점검 사물 목록 창과 같은 목록을 씁니다.
- 그리기만 하고 씬은 바꾸지 않습니다. 프리팹 편집 화면에서는 나오지 않습니다.

**개발 빌드** (메뉴 `Night Patrol → 개발 빌드`)

Development Build를 한 번에 만듭니다. Build Settings는 바꾸지 않습니다.

- 씬: `Assets/Scenes/Floor5.unity` 하나. 씬 담당이 Floor5에 Player·PatrolSystems를 놓은 뒤에 씁니다.
- 출력: `Builds/날짜_시각/NightPatrol.exe` (예: `Builds/2026-10-12_0723/`). `Builds/`는 git에 올라가지 않습니다.
- 끝나면 콘솔에 `[Build] 개발 빌드 성공 · 씬 1개 (…) · 대상 StandaloneWindows64 · … · 크기 · 걸린 시간` 한 줄이 나오고 폴더가 열립니다. 실패하면 `[Build] 개발 빌드 실패`와 오류 수가 나옵니다.
- 저장 안 한 씬이 있으면 먼저 저장할지 묻습니다. Play 중·컴파일 중에는 빌드하지 않습니다.
- 빌드하면 Unity가 공유 설정 파일을 다시 저장할 수 있습니다 (`Assets/Settings/`의 URP 설정 3개, `ProjectSettings/ProjectSettings.asset`·`UnityConnectSettings.asset`, ProBuilder 설정). 일부러 바꾼 게 아니면 커밋하지 말고 되돌리세요 (GitHub Desktop의 Discard).
- F1~F5 개발자 도구와 플레이테스트 기록은 개발 빌드에서만 동작합니다.
