# 야간순찰 시스템 가이드

플레이어·상호작용·점검 판정·층 진행·근무일지 시스템을 팀원이 쓰는 방법을 정리한 문서입니다.

> 담당: 양우성 (시스템) · 기준: 2026-10-06, `woosung` 브랜치 (PR #5 이후 작업 포함: 조준점·문구, 일지 구조, 층 이동 연출, 예외 지시, 기록 파일)
> 시스템 코드(`Assets/Scripts/` 아래 이 문서에 나오는 파일)를 고쳐야 할 것 같으면 직접 고치지 말고 말해 주세요. 대부분은 이벤트 구독이나 Inspector 설정으로 해결됩니다.

---

## 0. 한눈에 보기

### 핵심 루프

```
층 도착 → 근무일지 확인(Tab) → 점검·조치(E) → 엘리베이터(E)
   ├─ 점검 사물이 전부 정상 → 아래층 (마지막 층 도착 = 클리어)
   └─ 하나라도 비정상 → 실패: 회차 +1, 5층 시작 자리로
```

층은 같은 씬을 다시 씁니다. 층이 바뀌면 사물을 처음 상태로 되돌리고, 표지판·조명·이상현상만 바꿉니다 (기획서 4.2).

### 층이 시작될 때 일어나는 순서 (항상 이 순서)

1. 모든 점검 사물을 기본 상태로 되돌림 (`ResetToDefault`) + 이상현상 카운트 0
2. `PatrolRun.FloorStarted(층)` 이벤트 → 이상현상·표지판·조명은 여기서 바꿉니다
3. 점검 항목 표에서 2~3개를 뽑아 대상 사물을 비정상으로 만듦
4. 근무일지 갱신

2번에서 켠 이상현상의 대상은 3번에서 점검 항목으로 뽑히지 않습니다 (정상인 사물만 뽑기 때문).

### 조작 키 (설정 → 조작 키)

- 바꿀 수 있는 키: 앞으로·뒤로·왼쪽·오른쪽(WASD), 상호작용(E), 근무일지(Tab), 손전등(F). 고정: ESC(메뉴·취소), 마우스 시점, 메뉴 조작 키, 개발자 키(F1~F5, PgUp/PgDn)
- 줄을 고르면 "키를 누르세요" → 다음에 누른 키(키보드, 마우스 오른쪽·가운데·옆 버튼)로 바뀜, ESC는 취소. 다른 줄과 겹치면 두 줄의 키를 서로 바꿈. "기본값으로"는 전부 되돌림
- 바꾼 키와 설정(감도·소리·프레임 제한)은 PC에 저장되고(PlayerPrefs), 씬을 불러올 때마다 적용됩니다 — ESC 메뉴가 없는 씬에서도.
- 화면 문구는 사물의 `Prompt`가 `E - …`로 시작하면 앞의 E를 지금 상호작용 키로 바꿔 보여줍니다. 사물 코드는 지금처럼 `"E - 문 닫기"`라고 쓰면 됩니다.
- 목록은 `Assets/Settings/KeyBindingList.asset` 하나 (Create → Night Patrol → Key Binding List). 메뉴에는 10줄까지 나옵니다 (지금 7줄). 옮길 때는 Unity Project 창에서 끌어서 (탐색기로 옮기면 GUID가 바뀌어 메뉴 연결이 끊김). 줄마다 표시 이름 + 동작(InputActionReference) + 합성 파트(Move의 up/down/left/right, 단일 키면 비움).

새 키 동작을 추가할 때 (메뉴·저장·겹침 처리는 코드 수정 없이 그대로 됨):
1. `Assets/InputSystem_Actions` → Player 맵에 액션 추가, 기본 키 바인딩(Keyboard&Mouse 그룹). 이미 쓰는 키는 피하기 (아래 원칙)
2. `KeyBindingList`에 줄 하나 추가 (표시 이름 + 그 액션). 빠뜨리면 자동 테스트 `KeyBindingRulesTests`가 실패하며 알려 줍니다
3. 코드는 `KeyInput` 칸 하나로 씁니다. Inspector에서 그 액션을 연결하고, 비워 두면 대체 키로 동작합니다.

```csharp
using NightPatrol.Controls;
using UnityEngine.InputSystem;

[SerializeField] private KeyInput radioKey = new KeyInput(Key.Q);   // 액션을 연결하면 설정에서 바꾼 키, 비면 Q

private void Update()
{
    // KeyInput은 키만 읽는다. 메뉴·층 이동 연출·창 밖에서는 PlayerControl.CanAct가 false (using NightPatrol.Player)
    if (!PlayerControl.CanAct) return;
    if (radioKey.WasPressed()) ToggleRadio();   // IsPressed() · WasReleased() · KeyName("Q" 등 화면 표시용)도 있음
}
```
- `KeyInput`은 처음 쓸 때 액션을 켜고 끄지 않습니다. 입력 에셋의 액션은 여러 곳이 같이 쓰므로 직접 `Disable()`하거나 `Clone()`하지 마세요 (설정에서 바꾼 키가 안 먹거나 다른 기능이 멈춤).

기본 키 배정 원칙: 먼저 쓰기 시작한 사람의 키를 유지하고, 새 동작은 이미 쓰는 키를 피해서 고릅니다. 지금 쓰는 키: WASD·마우스, E(상호작용), Tab(근무일지), F(손전등), ESC(메뉴), F1~F5·PgUp/PgDn(개발자). 기본 키끼리 겹치면 자동 테스트가 실패합니다.

### 설정값 (`PlayerSettings` 에셋)

`Create → Night Patrol → Player Settings`로 만드는 ScriptableObject입니다. 지금 Player 프리팹은 `Assets/_Dev/woosung/PlayerSettings_Test.asset`을 씁니다.

| 값 | 기본 | 뜻 |
| --- | --- | --- |
| Walk Speed | 2 | 걷는 속도 (m/s) |
| Gravity | −9.81 | 중력 |
| Mouse Sensitivity | 0.1 | 마우스 감도 |
| Pitch Limit | 80 | 위아래로 볼 수 있는 최대 각도 |
| Interaction Distance | 2 | E가 닿는 거리 (m) |
| Aim Assist Radius | 0.05 | 조준 보정 (m). 가는 조준선이 빗나가도 이만큼 옆의 작은 대상(스위치 등)은 잡힘. 0이면 끔 |

마우스 감도·소리 크기·프레임 제한(기본 수직 동기)은 플레이어가 ESC 메뉴에서 바꾸고 PC에 저장됩니다 (PlayerPrefs, 감도는 위 값에 곱하는 배율). 해상도·화면 모드는 Unity가 기억합니다. 해상도·화면 모드·수직 동기는 빌드에서만 적용되고 에디터 Game 뷰는 그대로입니다. 에셋 값은 기본값입니다.

### 소리 (`PlayerSounds`, Player 루트)

소리 파일을 넣을 자리만 있고 지금은 비어 있습니다 (사운드 방향은 공동 결정). 파일을 넣으면 바로 납니다.

| 칸 | 언제 |
| --- | --- |
| Footsteps (여러 개) | 걸은 거리 0.9m마다 무작위 하나 (같은 소리 연달아 안 나옴, 높낮이 조금씩 다르게). 실패 후 순간이동은 발소리 없음 |
| Interact | E로 무언가를 조작했을 때 |
| Journal Raise / Lower | 일지를 들 때 / 내릴 때. ESC 메뉴를 열고 닫을 때도 |
| Descend / Arrive / Wake | 하행 시작 / 도착(띵) / 졸다 깸 |

- 전체 크기는 ESC 메뉴의 소리 크기(`AudioListener.volume`)를 따릅니다.
- 문 삐걱·이상현상 소리 같은 사물 소리는 각 사물의 AudioSource로 (이 컴포넌트는 플레이어 쪽만).

### 손에 드는 물체 (FirstPerson 레이어)

- 프로젝트 레이어 6번 `FirstPerson`은 손에 든 물체 전용입니다. 메인 카메라에는 안 그려지고 `ViewModelCamera`가 따로 그려서 벽에 가까이 가도 물체가 벽에 박히지 않습니다.
- 손전등 같은 손에 드는 모델은 `PlayerCamera` 아래에 두고 레이어를 `FirstPerson`으로 하면 됩니다.
- 손에 든 물체에는 콜라이더를 붙이지 마세요 (E 조준을 가릴 수 있음).

### 다른 코드에서 쓸 수 있는 기능

조작 잠금은 "누가 잠갔는지"별로 따로 관리합니다. 여러 곳이 동시에 잠가도 각자 자기 것만 풀기 때문에 서로 꼬이지 않습니다. 플레이어 전체를 멈출 때는 `PlayerControl.Lock` 한 번, 일부만 막을 때는 컴포넌트별 `SetBlocked`를 씁니다. 지금 누가 잠갔는지는 F1 "자세히"의 **조작 잠금** 구역에 보입니다.

| 컴포넌트 | 기능 | 설명 |
| --- | --- | --- |
| `PlayerControl` | `Current`, `Lock(this, true/false)`, `IsLocked` | 플레이어 전체 잠금 (이동·시점·E·일지를 한 번에). `Lock(this, 잠금, includeJournal: false)`이면 일지는 그대로. 잠글 때와 풀 때 같은 값으로 |
| `PlayerControl` | `CanAct` (static) | 게임 동작 키를 받아도 되는지: ESC 메뉴(시간 정지)·층 이동 연출(잠금)·커서가 풀림·창 밖이면 false. 일지를 든 동안은 true |
| `PlayerInteractor` | `SetBlocked(this, true/false)`, `IsBlocked` | E 상호작용 잠금 |
| `PlayerMovement` | `SetBlocked(this, true/false)`, `IsBlocked` | 이동 잠금 (중력은 그대로) |
| `PlayerLook` | `SetBlocked(this, true/false)`, `IsBlocked` | 시점 회전 잠금 |
| `JournalHolder` | `SetBlocked(this, true/false)`, `IsBlocked` | 일지 들기(Tab) 잠금. 잠그면 들고 있던 일지를 내림 |
| `PlayerMovement` | `Teleport(위치, 회전)` | 순간이동. 회전은 좌우만 쓰고, 낙하 속도와 위아래 시선도 초기화 |
| `PlayerInteractor` | `CurrentTarget`, `TargetChanged` | 지금 조준 중인 대상과 바뀔 때 이벤트 |
| `PlayerInteractor` | `Interacted` | E로 무언가를 조작한 직후 이벤트 (조작 소리, 이상현상 반응 등) |
| `PlayerLook` | `SetPitch(각도)` | 위아래 시선을 직접 정함 (+ 아래 / − 위, 연출용) |
| `PlayerInteractor` | `HoldProgress` | E 길게 누르기 진행도 (0~1) |
| `PlayerInteractor` | `InteractAction` | 상호작용 입력 액션 (지금 키 이름 표시 등) |
| `KeyBindings` | `KeyName(액션, 바인딩 번호)`, `Changed` | 지금 키 이름 ("W", "Tab", "마우스 오른쪽"), 키를 바꿨을 때 이벤트 |
| `JournalHolder` | `SetMenuOpen(bool)`, `IsMenuOpen` | 일지 상태와 따로 클립보드를 들어 올림 (ESC 메뉴가 씀) |
| `PauseMenu` | `IsOpen`, `CurrentPage`, `OpenChanged`, `Open()`, `Close()` | ESC 메뉴. 열린 동안 `Time.timeScale = 0`, 소리 일시정지, 마우스 커서 보임. 처음으로 = 지금 씬을 다시 불러 5층 1회차부터 |

```csharp
// 연출 동안 플레이어를 멈추는 예 (using NightPatrol.Player)
var player = PlayerControl.Current;          // 씬의 플레이어 (없으면 null)
if (player != null) player.Lock(this, true); // 이동·시점·E·일지
// ... 연출 끝나면
if (player != null) player.Lock(this, false);
```

> 잠근 쪽이 꺼지거나 사라질 때(`OnDisable`) 꼭 `false`로 풀어 주세요. 안 풀면 계속 잠겨 있습니다.

## 2. 상호작용 (E)

### 동작 방식

- 화면 가운데에서 앞으로 레이를 쏴서 2m(Interaction Distance) 안의 첫 콜라이더를 찾습니다. 레이가 대상을 못 맞히면 반지름 5cm(Aim Assist Radius) 구로 한 번 더 찾습니다 — 작은 스위치·잠금장치도 조준하기 쉽게. 벽이 먼저 닿으면 그 뒤는 안 봅니다.
- 맞은 콜라이더나 그 부모에 `IInteractable`이 있으면 대상이 됩니다. 그래서 대상 오브젝트(또는 자식)에 콜라이더가 꼭 있어야 합니다.
- Trigger 콜라이더와 `Ignore Raycast` 레이어는 무시합니다. 벽도 레이를 막습니다.
- 컴포넌트가 꺼져 있으면 대상이 아닙니다.
- E는 누르는 순간 반응합니다 (Input 에셋에 Hold가 있어도 기다리지 않음).
- 되돌리기 어려운 조작은 E를 길게 누르게 할 수 있습니다: `IInteractable` 대신 `IHoldInteractable`을 구현하고 `HoldSeconds`(초)를 추가. 누르는 동안 조준점 둘레 링이 차고(`Prompt`가 빈 문자열이면 링도 안 보임), 떼거나 다른 곳을 보면 처음부터. 엘리베이터가 0.7초 (실수로 한 번 눌러 실패하지 않게).
- 조작할 수 있는 대상을 보면 화면 가운데 아래에 그 대상의 `Prompt` 문구가 뜹니다. 일지를 든 동안·ESC로 커서를 푼 동안은 조준점과 문구가 숨습니다. E를 누르면 조준점이 잠깐 커집니다.
- 문구가 빈 문자열인 대상은 조작할 게 없는 것으로 보고 조준점이 흐리게 남습니다.

### 상호작용 대상 만들기

점검 대상이 아니라 그냥 E로 누르는 물건(스위치, 전화 등)은 `IInteractable`만 구현하면 됩니다.

```csharp
using NightPatrol.Interaction;
using UnityEngine;

public class BreakerSwitch : MonoBehaviour, IInteractable
{
    public string Prompt => "E - 차단기 내리기";   // 조준하면 보일 문구 (빈 문자열이면 안 보임)

    public void Interact(PlayerInteractor who)
    {
        Debug.Log("차단기 내림");
    }
}
```

점검 대상(정상/비정상이 있는 것)이면 `IInteractable` 대신 아래 `PatrolObject`를 상속합니다.

## 3. 점검 사물 (PatrolObject)

### 개념

- 점검 사물은 정상/비정상 상태가 있는 물건입니다 (전등, 문, 창문, 블라인드, 모니터 등).
- 엘리베이터를 탈 때 씬에 켜져 있는 모든 점검 사물이 정상이어야 아래층으로 갑니다. 하나라도 비정상이면 실패입니다.
- 꺼진(비활성) 사물은 판정에서 빠집니다.

### 상속할 때 구현할 것

| 멤버 | 필수 | 설명 |
| --- | --- | --- |
| `IsNormal` | 필수 | 규정상 정상이면 true (예: 전등이 꺼져 있음, 문이 잠겨 있음) |
| `ResetToDefault()` | 필수 | 처음 상태로 되돌리기. 층이 시작될 때마다 불림. 처음 상태는 반드시 정상 |
| `Prompt` | 필수 | 조준했을 때 문구 (예: "E - 전등 끄기") |
| `Interact(who)` | 필수 | E를 눌렀을 때 동작 |
| `TrySetAbnormal()` | 선택 | 점검 항목으로 뽑혔을 때 비정상으로 바꾸고 true. 지원 안 하면 override하지 않음 (기본 false) |
| `Id` | Inspector | `구역.종류.번호` (예: `R21.Monitor.03`, `Corridor.Lamp.01`) |

부모가 알아서 하는 것:

| 멤버 | 설명 |
| --- | --- |
| `IsClear` | `IsNormal`이면서(예외 지시면 반대) 이상현상도 없음. 판정은 이 값을 봅니다 |
| `IsException` | 이번 층 예외 지시 대상인지 (4장). 점검 항목 표가 정하고 층이 시작되면 풀림 |
| `HasAnomaly`, `AddAnomaly()`, `RemoveAnomaly()` | 이상현상 카운트 (6장) |

### 예시: 모니터

```csharp
using NightPatrol.Interaction;
using NightPatrol.Patrol;
using UnityEngine;

public class PatrolMonitor : PatrolObject
{
    [SerializeField] private Renderer screen;
    [SerializeField] private Material onMaterial, offMaterial;
    private bool isOn;

    public override bool IsNormal => !isOn;                      // 규정 제2조: 전자기기는 꺼져 있어야 정상
    public override string Prompt => isOn ? "E - 모니터 끄기" : "E - 모니터 켜기";

    private void Awake() => ResetToDefault();
    public override void ResetToDefault() => SetOn(false);       // 처음 상태 = 정상
    public override void Interact(PlayerInteractor who) => SetOn(!isOn);

    public override bool TrySetAbnormal()                        // 점검 항목으로 뽑히면 켜짐
    {
        SetOn(true);
        return true;
    }

    private void SetOn(bool on)
    {
        isOn = on;
        if (screen != null) screen.sharedMaterial = on ? onMaterial : offMaterial;
    }
}
```

### 체크리스트

- 처음 상태(`ResetToDefault`)가 정상인가? 아니면 일지에는 없는데 판정에 걸립니다. 층 시작 때 콘솔에 `[Run] 초기화 직후 비정상` 경고가 뜹니다.
- `Awake`에서 `ResetToDefault()`를 부르는가?
- 조준할 수 있게 콜라이더가 있는가?
- `Id`가 비어 있지 않고 다른 사물과 겹치지 않는가?

### Id 규칙

- 형식: `구역.종류.번호` — 구역 `R21`(521호), `Corridor`, `StairW` 등 / 종류 `Door`, `Window`, `Blind`, `Lamp`, `Monitor` 등 / 번호 `01`부터
- 층 번호는 넣지 않습니다 (모든 층이 같은 씬).
- 맵 생성기(FloorGenerator)가 만든 문·창문·블라인드·모니터·TV는 Id가 자동으로 붙습니다 (생성 순서대로 번호). 손으로 놓은 사물은 직접 적습니다. 생성기에 새 종류의 점검 사물을 추가하면 Id 부여에도 그 종류를 넣어야 합니다 (송지우님).
- 생성기가 만든 오브젝트에 손으로 컴포넌트를 붙이거나 직접 참조하면, Generate Floor를 다시 할 때 사라집니다. 다른 코드에서는 Id로 찾으세요: `PatrolInspection.FindById("R21.Door.01")`.

### 지금 있는 점검 사물

| 클래스 | 담당 | 정상 | 점검 항목 지원 (`TrySetAbnormal`) |
| --- | --- | --- | --- |
| `PatrolLamp` | 시스템 담당 (예시) | 전등 꺼짐 | 있음 (켜짐) |
| `Door` | 송지우님 | 닫히고 잠김 | 있음 (잠금 해제 + 열림) |
| `WindowUnit` | 송지우님 | 닫히고 잠김 | 있음 (잠금 해제 + 열림) |
| `WindowBlind` | 송지우님 | 규정 쪽(보통 내려감) | 있음 (반대 상태) |
| `MonitorDevice` | 송지우님 | 꺼짐 (모니터 `R21.Monitor.01~`, 천장 TV `R24.TV.01~02`) | 있음 (켜 둠) |

`TrySetAbnormal`이 false를 돌려주면(예: 문짝·화면이 연결 안 됨) 그 사물은 점검 항목으로 뽑히지 않습니다.

### 판정·검색 도구 (`PatrolInspection`)

| 기능 | 설명 |
| --- | --- |
| `IsAllClear()` | 켜진 점검 사물이 전부 정상인지 (엘리베이터가 씀) |
| `FindAbnormal()` | 비정상 사물 목록 (Id 순). 매 프레임 부르지 마세요 |
| `FindById(id)` | Id로 사물 찾기 (꺼진 것 포함). 없으면 null. 층 시작 때 만든 표를 써서 빠름 (없거나 파괴됐으면 다시 검색) |
| `MapById()` | Id → 사물 표. 중복 Id는 경고 |

## 4. 점검 항목 표 (TaskTable)

### 동작

- 층이 시작될 때 표에서 2~3개를 뽑아, 각 항목의 대상 사물을 비정상으로 만들고 근무일지에 문구를 적습니다.
- 점검 항목은 "이번 층에 특별히 확인할 것"입니다. 규정(전자기기 꺼짐, 출입문 잠김)은 항상 적용되므로, 표에 없는 사물도 비정상이면 판정에 걸립니다.

### 만드는 법

1. Project 창 우클릭 → `Create → Night Patrol → Task Table`
2. Entries에 항목 추가

| 필드 | 설명 |
| --- | --- |
| Label | 일지에 적힐 문구 (예: `524호 블라인드 내리기`). 비우면 대상 Id가 적힘 |
| Ids | 대상 사물 Id. 여러 개면 그중 하나만 비정상이 됨 |

- 일지에는 표 순서대로 적힙니다. 권장 순찰 순서(형광등 켜고 개폐 확인 → 소등 → 손전등)대로 배치하세요 (기획서 3.6).
- 여러 사물을 하나로 묶을 때 Ids에 여러 개를 넣습니다. 예: Label `교수실 구역 잠금 확인`, Ids `R05.Door.01` ~ `R17.Door.01` → 그중 한 문만 열림.
- 대상 사물이 `TrySetAbnormal()`을 지원해야 뽑힙니다.

### 예외 지시 (기획서 3.5 내용 판단형)

- 항목의 `Exception`을 체크하면, 뽑힌 대상이 비정상 상태(예: 켜짐)로 시작하고 이번 층에는 그 상태가 정상입니다.
- 예: Label `521호 강사 PC는 업데이트 중 — 끄지 말 것`, Ids `R21.PC.01`, Exception 체크 → 규정대로 다 끄고 다니면 실패, 일지를 읽고 켜 둬야 통과
- 일지에는 표시 방식(목록·개수만·?건)과 상관없이 항상 `※ 문구`로 보이고, "점검 사항 N건"에는 세지 않습니다 (개수만 보이는 층에서 숨기면 알 방법이 없어 반드시 실패하므로).
- 층이 바뀌면 예외는 풀립니다. 같은 사물이 예외와 일반 항목에 동시에 뽑히지 않습니다.
- 사물 클래스는 고칠 필요가 없습니다 (`TrySetAbnormal`만 있으면 됨).

### 표 연결 (`FloorTasks` 컴포넌트, 보통 PatrolRun과 같은 오브젝트)

| 값 | 기본 | 설명 |
| --- | --- | --- |
| Table | — | 위에서 만든 표 |
| Min Tasks / Max Tasks | 2 / 3 | 층마다 뽑는 개수 |
| Seed | 0 | 0이면 매번 랜덤. 다른 숫자면 같은 층·회차에 항상 같은 항목 (테스트용) |

다른 코드에서 이번 층 항목이 필요하면 `FloorTasks.CurrentTasks`(각 항목의 `Label`, `Target`)와 `TasksChanged` 이벤트를 쓰세요.

## 5. 층 진행 (PatrolRun, Elevator)

### 씬에 놓기

- 빈 오브젝트에 `PatrolRun`과 `FloorTasks`를 붙이고 FloorTasks의 Table을 지정합니다. 씬에 하나만 둡니다. (Floor5 빌드 작업 이후에는 이 둘을 묶은 `PatrolSystems` 프리팹을 하나 놓으면 됩니다.)
- 엘리베이터 버튼(또는 문) 오브젝트에 `Elevator`와 콜라이더를 붙입니다. E를 0.7초 눌러야 내려갑니다 (Hold Seconds, 0이면 한 번).
- Player 프리팹을 5층 경비 데스크 자리에 놓습니다.
- 참조는 비워 두면 씬에서 알아서 찾습니다 (Player, FloorTasks, Elevator의 Run).

### Inspector (`PatrolRun`)

| 값 | 기본 | 설명 |
| --- | --- | --- |
| Floors | 5, 4, 3, 2, 1 | 내려가는 층 순서. 마지막 층 도착 = 클리어. 최소 구성은 5, 3, 1 |
| Start Point | 비어 있음 | 실패하면 돌아오는 자리. 비우면 플레이어가 처음 서 있던 자리 |
| Player | 자동 | `PlayerMovement` |
| Tasks | 자동 | `FloorTasks` |

### 읽을 수 있는 값

| 값 | 설명 |
| --- | --- |
| `CurrentFloor` | 지금 층 번호 |
| `Attempt` | 회차 (1부터, 실패할 때마다 +1) |
| `IsCleared` | 마지막 층에 도착했는지 |
| `FailedFloors` | 실패한 층 목록 (실패한 순서대로) |
| `IsFirstFloor` | 지금 첫 층(보통 5층)인지 |

### 이벤트 (팀원 코드는 이걸 구독)

| 이벤트 | 언제 | 쓰는 곳 예시 |
| --- | --- | --- |
| `FloorReset(int 층)` | 층이 시작될 때 맨 먼저: 점검 사물 초기화 직후, `FloorStarted` 전 | 점검 사물이 아닌데 층마다 처음 상태로 돌아가야 하는 것 (조명 구역 등). 이상현상은 여기서 켜지 말 것 |
| `FloorStarted(int 층)` | `FloorReset` 다음, 점검 항목 생성 전 (게임 시작, 하행, 실패 후 5층) | 이상현상 켜기, 표지판 숫자 |
| `Failed(int 실패한 층)` | 실패했을 때. 바로 다음에 5층 `FloorStarted`가 옴 | 실패 연출, 소리 |
| `Cleared()` | 마지막 층(1층)에 도착 | 이상현상 끄기, 엔딩 |

- 구독한 코드에서 오류가 나도 콘솔에 빨갛게 뜰 뿐 게임은 계속 진행됩니다 (다른 구독자와 점검 항목 생성도 그대로 진행). 이 문서에 나오는 시스템 이벤트는 모두 같습니다 (`TasksChanged`, 층 이동 연출, `Interacted`, `RaisedChanged` 포함).
- 1층 도착(`Cleared`)에는 `FloorStarted`가 오지 않습니다.
- 개발자 키 F4(층 재시작)·PgUp/PgDn(층 이동)으로도 `FloorReset`·`FloorStarted`가 옵니다.
- 왜 시작됐는지는 `run.LastStart`로 압니다: `GameStart`·`Descend`(하행 성공)·`Fail`·`Restart`(F4)·`Jump`(PgUp/PgDn). 예: 하행 성공 때만 다음 이상을 켜려면 `run.LastStart == FloorStartReason.Descend`.
- 사물 하나의 코드 오류(`ResetToDefault`·`TrySetAbnormal`·`IsNormal`의 예외)는 그 사물만 건너뛰고 층 시작은 끝까지 갑니다. `IsNormal`이 예외를 내는 사물은 **비정상**으로 셉니다 (조용히 통과시키지 않음, 오류 로그는 층마다 한 번).
- 팀원 사물의 이벤트(`Door`·`WindowUnit`·`WindowBlind`·`MonitorDevice`의 `StateChanged`, `ElevatorDoors`의 `Opened`·`Closed`, `LightZone.Changed`, `Flashlight.Toggled`)는 위와 달리 구독자 오류가 그대로 전파됩니다 (예: 문 소리 구독자 오류 → 잠금만 풀리고 문은 안 열림). 구독하는 쪽에서 오류가 나지 않게 하세요. 또 층이 시작될 때 사물 초기화(`SetStateImmediate`)에서도 `StateChanged`가 오므로, 소리를 붙일 때는 층 시작 때 울리지 않게 하세요.

```csharp
using NightPatrol.Run;
using TMPro;
using UnityEngine;

// 예: 층이 바뀌면 호수 표지판 앞자리를 바꿈 (521 → 421)
public class RoomSign : MonoBehaviour
{
    [SerializeField] private TMP_Text label;
    [SerializeField] private string roomNumber = "21";
    private PatrolRun run;

    private void Awake() => run = FindAnyObjectByType<PatrolRun>();
    private void OnEnable() { if (run != null) run.FloorStarted += OnFloorStarted; }
    private void OnDisable() { if (run != null) run.FloorStarted -= OnFloorStarted; }

    private void OnFloorStarted(int floor) => label.text = $"{floor}{roomNumber}";
}
```

### 층 이동 연출 (`FloorTransition`, Player 프리팹 HUD)

엘리베이터 E → 조작 잠금 → (엘리베이터 문 닫힘) → 화면 어두워짐 → 어두운 동안 판정·층 바꾸기 → "N층" → 밝아짐 → (문 열림) → 잠금 해제.
실패하면 어두운 동안 시작 자리로 옮겨진 뒤 깜빡이며 고개를 드는 "졸다 깨는" 연출이 나옵니다 (개발자 메뉴 F3도 같음). 게임 시작 때는 검은 화면에서 밝아집니다.

| 이벤트 | 언제 | 예시 |
| --- | --- | --- |
| `DescendStarted` | 하행 연출 시작 | 버튼음, 문 닫히는 소리 |
| `Arrived(int 층)` | 하행 성공, "N층"을 띄우기 직전 | "띵" 소리 |
| `WakeStarted` | 졸다 깨는 연출 시작 | 숨 들이쉬는 소리 |

```csharp
using NightPatrol.Run;
using UnityEngine;

// 예: 엘리베이터 도착음
public class ElevatorDing : MonoBehaviour
{
    [SerializeField] private AudioSource ding;
    private FloorTransition transition;

    private void Awake() => transition = FindAnyObjectByType<FloorTransition>();
    private void OnEnable() { if (transition != null) transition.Arrived += OnArrived; }
    private void OnDisable() { if (transition != null) transition.Arrived -= OnArrived; }

    private void OnArrived(int floor) => ding.Play();
}
```

- 엘리베이터 문: 송지우님의 `ElevatorDoors`(Elevator_Base 프리팹 루트, 문짝 `Door_Left`·`Door_Right`, 층 표시)를 씁니다. 하행 연출이 문 닫기 → 닫힐 때까지 대기 → 어두워짐·판정·층 이동 → 밝아짐 → 문 열기 순서로 부릅니다. 문이 끝까지 안 움직여도 `Move Seconds` + 0.5초 뒤에는 연출이 계속됩니다. 문이 없거나 꺼져 있으면 문 연출만 빠집니다.
- 연출 중에는 이동·시점·E·일지(Tab)가 모두 잠기고, 들고 있던 일지는 내려갑니다. 엘리베이터 문구도 사라지고 다시 눌리지 않습니다.
- 위 이벤트를 구독한 코드나 판정 중에 오류가 나도 연출은 끝까지 가고 잠금이 풀립니다. 사물 코드 오류는 그 사물을 비정상으로 세므로 보통 "실패"가 되고, 진행 코드 자체의 오류면 "N층" 없이 밝아지며 콘솔에 `[Transition] 하행 판정 중 오류`가 뜹니다.
- `FloorTransition`을 끄면 엘리베이터는 연출 없이 바로 하행합니다.

### 메서드 (주로 개발자 메뉴·테스트용)

| 메서드 | 설명 |
| --- | --- |
| `TryDescend()` | 판정 후 하행 또는 실패 (엘리베이터가 부름) |
| `Descend(bool allClear)` | 판정 결과를 직접 넣어 하행/실패 |
| `Fail()` | 실패 처리 |
| `RestartFloor()` | 지금 층 다시 시작 (사물 초기화 + 항목 다시 뽑기) |
| `JumpBy(int)` | 층 이동 (−1 위층, +1 아래층) |

## 6. 이상현상 연결 (이상 상태 담당)

### 규칙

1. 이상현상은 `FloorStarted`에서 켭니다. `Start()`에서 켜면 층 시작 초기화와 순서가 꼬여 카운트가 지워지거나 점검 항목과 겹칩니다. 층마다 되돌리는 것(조명 구역 등)은 그 전 단계 `FloorReset`에서 끝나므로 `FloorStarted`에서 바꾼 것이 덮이지 않습니다 — 단 `LightZone`은 아직 `FloorStarted`에서 복구합니다 (송지우님께 `FloorReset`으로 옮겨 달라고 요청함). 그 전까지는 조명 이상현상이 바로 다시 켜질 수 있습니다.
2. 이상이 걸린 동안 대상 사물에 `AddAnomaly()`를 해 두면, 사물이 정상이어도 판정에 걸립니다. 해결되면 `RemoveAnomaly()`.
3. 층이 시작될 때 이상 카운트는 시스템이 0으로 만듭니다. 그래서 `FloorStarted`에서는 이전 층 이상의 **겉모습만** 되돌리고 `RemoveAnomaly()`는 부르지 마세요 — 다른 이상현상이 이번 층에 같은 사물에 건 카운트까지 지워집니다. `RemoveAnomaly()`는 층 도중에 해결됐을 때, `Cleared`, 꺼질 때(`OnDisable`)에 부릅니다.
4. 대상은 Id로 찾습니다: `PatrolInspection.FindById("R21.Monitor.03")`. 생성된 오브젝트에 직접 붙이거나 참조하지 마세요 (Generate Floor 때 사라짐).
5. 첫 회차 5층(`run.Attempt == 1 && floor == 5`)은 이상현상 없이 점검 항목만 있습니다 (기획서 3.4).
6. 1층 도착(`Cleared`)에는 `FloorStarted`가 오지 않으니 `Cleared`에서도 끄세요.
7. 점검 항목은 `FloorStarted` 다음에 정상인 사물 중에서 뽑히므로, 이상 대상과 겹치지 않습니다.
8. 모니터·TV 화면은 재질을 직접 바꾸지 말고 `MonitorDevice.OverrideScreen(재질)` / `ClearScreenOverride()`를 씁니다 (켜고 끌 때 덮어써지지 않게).

### 예시

```csharp
using NightPatrol;          // MonitorDevice (송지우님)
using NightPatrol.Patrol;
using NightPatrol.Run;
using UnityEngine;

public class MonitorAnomalyManager : MonoBehaviour
{
    [SerializeField] private string[] targetIds = { "R21.Monitor.03", "R21.Monitor.07" };
    [SerializeField] private Material anomalyScreen;
    private PatrolRun run;
    private PatrolObject current;

    private void Awake() => run = FindAnyObjectByType<PatrolRun>();
    private void OnEnable()
    {
        if (run == null) return;
        run.FloorStarted += OnFloorStarted;
        run.Cleared += OnCleared;
    }
    private void OnDisable()
    {
        if (run != null)
        {
            run.FloorStarted -= OnFloorStarted;
            run.Cleared -= OnCleared;
        }
        TurnOff(true);   // 꺼질 때는 걸어 둔 이상까지 푼다
    }

    private void OnFloorStarted(int floor)
    {
        TurnOff(false);   // 카운트는 시스템이 이미 0으로 만들었다 — 겉모습만 되돌림 (규칙 3)
        if (run.Attempt == 1 && floor == 5) return;      // 첫 회차 5층은 이상 없음
        current = PatrolInspection.FindById(targetIds[Random.Range(0, targetIds.Length)]);
        if (current == null) return;
        if (current is MonitorDevice monitor) monitor.OverrideScreen(anomalyScreen);   // 규칙 8
        current.AddAnomaly();
    }

    private void OnCleared() => TurnOff(true);

    // 플레이어가 층 도중에 해결했을 때(예: 전화 안내 → 스위치)도 TurnOff(true)
    private void TurnOff(bool removeCount)
    {
        if (current == null) return;
        if (current is MonitorDevice monitor) monitor.ClearScreenOverride();
        if (removeCount) current.RemoveAnomaly();
        current = null;
    }
}
```

### 일지 바꾸기 (`IJournalModifier`)

이상현상이 근무일지 내용을 바꿔야 할 때(기획서 3.8 "지시가 이상함" 등) 일지 코드를 고치지 않고 수정자를 등록합니다.
일지가 갱신될 때마다 `JournalPage`(한 장의 내용)를 받아 고치면 됩니다.

```csharp
using NightPatrol.Journal;
using UnityEngine;

public class WrongCountAnomaly : MonoBehaviour, IJournalModifier
{
    private JournalView journal;

    private void Awake() => journal = FindAnyObjectByType<JournalView>();
    public void Activate() => journal.AddModifier(this);      // FloorStarted에서
    public void Deactivate() => journal.RemoveModifier(this);
    private void OnDisable() { if (journal != null) journal.RemoveModifier(this); }

    public void ModifyJournal(JournalPage page)
    {
        if (page.Display == TaskDisplay.List && page.Tasks.Count > 0)
            page.Tasks.RemoveAt(page.Tasks.Count - 1);          // 목록에서 한 줄이 빠짐
        else
            page.CountOverride = page.Tasks.Count + 1;          // "N건"이 실제와 다름
    }
}
```

| `JournalPage`에서 바꿀 수 있는 것 | 예 |
| --- | --- |
| `Title` | 제목 바꾸기 |
| `Notes` (맨 위 메모) | 메모 덩어리 추가 |
| `Rules` | 규정 문구 바꾸기 (`<color=#8a0000>…</color>` 같은 TMP 리치 텍스트 가능) |
| `Tasks` | 점검 사항 줄 빼기·더하기·바꾸기 (처리할 것, "N건"이 세는 것) |
| `Exceptions` | 예외 지시 줄 (`※`로 항상 보임) |
| `Display`, `CountOverride` | 표시 방식, "N건"의 숫자 |
| `ClearedText` | 1층 완료 글 (기획서 4.3 "확신을 준 뒤 배신") |

- 등록 순서대로 적용됩니다. 한 수정자에서 오류가 나도 콘솔에 뜨고 나머지는 적용됩니다.
- 끌 때 꼭 `RemoveModifier`로 해제하세요. 오브젝트가 파괴되면 자동으로 빠지지만, 컴포넌트를 끄기만 하면 계속 적용됩니다.

### 형태별 힌트 (기획서 3.8)

| 형태 | 방법 |
| --- | --- |
| 꺼지지 않음 | `AddAnomaly()` + 화면을 계속 켠 모습으로. 해결(전화 안내 → 스위치) 시 `RemoveAnomaly()` |
| 되돌아옴 | `Update`에서 대상의 `IsNormal`을 보다가, 플레이어가 끄면(정상이 되면) 잠시 뒤 `TrySetAbnormal()`로 다시 켬 |
| 지시가 이상함 | 일지 수정자로 건수·줄을 바꾸거나, 점검 항목이 아닌 사물에 `AddAnomaly()` → 일지와 실제가 어긋남 |
| 상태가 어긋남 | 빨간 전등 등 점검 사물을 비정상(켜짐)으로. 플레이어가 끄면 해결 |

## 7. 근무일지 (클립보드)

- Tab으로 눈앞에 들고 내립니다. 든 동안은 E 조작이 막힙니다 (Clipboard의 `JournalHolder` → Block Interaction While Raised를 끄면 들고도 조작 가능).
- 층 이동 연출 중에는 Tab이 먹지 않고, 들고 있던 일지는 내려갑니다.
- ESC 메뉴는 같은 클립보드를 들어 올려 일지 장 대신 메뉴 장을 보여줍니다. 메뉴가 열린 동안 Tab은 무시, 닫으면 원래 일지로.
- 표시 순서: 지난 순찰 기록(있으면) → 야간 순찰 규정 → 점검 사항. 1층 도착 시 `점검 완료. 퇴근하십시오.`
- 규정 문구는 Player 프리팹 → `JournalCanvas`의 `JournalView` → Rules에서 고칩니다.
- 한글은 Noto Sans KR이 TMP 기본 Fallback으로 등록되어 있어서 따로 설정할 필요가 없습니다.

### 층별 정보량 (기획서 3.4) — `JournalView` → Displays

| 층 | 기본 표시 | 일지 |
| --- | --- | --- |
| 5, 4 | List | 점검 사항 목록 |
| 3 | Count | "점검 사항 N건" |
| 2 | Unknown | "점검 사항 ?건" |
| 1 | — | "점검 완료. 퇴근하십시오." |

- 재미 검증 결과에 따라 Inspector에서 바로 바꿀 수 있습니다. `AtMost`는 "점검 사항 N건 이하" (N = FloorTasks의 Max Tasks, 기획서 3.4의 대체안)

### 지난 순찰 기록 (기획서 3.3) — `JournalView` → Failure Record

- 실패하면 `■ 지난 순찰 · 1회차 — 4층 실패`처럼 실패한 층만 적습니다 (무엇을 놓쳤는지는 안 알려줌). 최근 3회까지, 그 전은 "그 전 N회 생략"
- `FirstFloor`(기본): 첫 층(일지 첫 장)에서만 / `EveryFloor`: 모든 층 / `Off`: 안 보임

## 8. 개발자 도구 (에디터·개발 빌드에서만)

| 키 | 동작 |
| --- | --- |
| F1 | 개발자 정보 표시: 누를 때마다 끔 → 간단(한 줄: 층·회차·이 층 시간·FPS) → 자세히(패널) → 끔. 끔이 아닐 때만 아래 키가 동작 |
| F2 | 판정 무시하고 하행 |
| F3 | 강제 실패 |
| F4 | 지금 층 다시 시작 (사물 초기화 + 항목 다시 뽑기) |
| F5 | 기록 폴더 열기 (게임 로그 `logs/`, 플레이테스트 기록 `playtest/`) |
| PgUp / PgDn | 위층 / 아래층 이동 (맨 위·맨 아래에서는 무반응) |

F2~F5·PgUp/PgDn은 F1 표시를 켠 동안에만 동작합니다 (플레이테스트 때 테스터가 F3·F5를 실수로 누르지 않게). 키 안내는 F1 "자세히" 패널 맨 아래에 있습니다. 일반 빌드에서는 전부 동작하지 않습니다.

"자세히" 패널 구역: 진행 · 점검 항목(처리됨 초록 ● / 남음 빨강 ○ / 예외 노랑) · 비정상 사물 · 조준 대상(이름·거리·문구·상태) · (다른 코드가 붙인 구역) · 개발자 키.

- 층 이동 연출 중과 ESC 메뉴가 열린 동안에는 F2~F4·PgUp/PgDn을 무시합니다 (F5는 동작).
- 개발자 키로 넘긴 층은 플레이테스트 기록의 결과 칸에 `F2 하행`·`F3 실패`·`F4 재시작`·`층 이동`으로 남아 실제 결과와 섞이지 않습니다.

### F1 패널에 내 구역 추가 (`DevInfo`)

이상현상 상태처럼 개발 중에 보고 싶은 정보는 시스템 코드를 고치지 않고 구역으로 붙입니다. 글을 만드는 함수는 초당 4번만 불리고, 오류가 나도 패널에 빨간 글로 뜰 뿐입니다. 일반 빌드에서는 불러도 아무 일도 안 합니다.

```csharp
using NightPatrol.Debugging;
using UnityEngine;

// 예: 지금 켜진 이상현상을 F1 패널에 보이기
public class AnomalyDebugInfo : MonoBehaviour
{
    private string current = "없음";

    private void OnEnable() => DevInfo.Register(this, "이상현상", () => current);
    private void OnDisable() => DevInfo.Unregister(this);

    public void Show(string anomaly) => current = anomaly;   // 이상현상을 켤 때 불러 줌
}
```

- 순서는 `order`로 (기본 100): 진행 0, 점검 항목 10, 비정상 20, 조준 30, 개발자 키 200. 색은 `DevInfo.Paint(글, DevInfo.BadColor)` 같은 리치 텍스트로.

### 기록 파일

| 파일 | 위치 | 내용 | 언제 |
| --- | --- | --- | --- |
| 게임 로그 | `logs/game_날짜_시각.log` | 콘솔 메시지 전부 + 시각, 오류는 스택까지, 맨 위에 PC 정보 | 에디터 Play·모든 빌드, 실행마다 하나 (최근 20개 유지) |
| 플레이테스트 기록 | `playtest/날짜_시각.csv` | 층마다 회차·층·결과(통과·실패·중단, 마지막 줄 클리어)·걸린 시간·E 횟수·일지 본 횟수·점검 항목 | 에디터·개발 빌드 (Player의 PlaytestLog) |

## 11. 협업 규칙과 자주 하는 실수

- `Assets/Fonts/*SDF.asset`, `LiberationSans SDF - Fallback.asset`은 Play하면 글자 아틀라스가 저장되어 변경으로 뜹니다. 커밋하지 말고 되돌려 주세요 (`git checkout -- 파일`).
- `ProjectSettings/`가 에디터 작업 중 저절로 바뀌는 경우가 있습니다. 의도한 변경이 아니면 커밋하지 마세요.
- 씬은 동시에 편집하지 않습니다 (기획서 8.2). Floor5는 송지우님 담당.
- 이상현상을 `Start()`에서 켜지 않기 → `FloorStarted`
- 생성된 오브젝트에 손으로 컴포넌트 붙이지 않기 → Id로 찾기
- 점검 사물의 처음 상태는 정상
- 손에 드는 물체는 `FirstPerson` 레이어, 콜라이더 없이
- ESC 메뉴가 열리면 `Time.timeScale = 0`, `AudioListener.pause = true`입니다. 이상현상·연출은 `Time.deltaTime`(기본)과 일반 AudioSource를 쓰면 메뉴 동안 같이 멈춥니다. 메뉴 중에도 움직여야 하는 것만 `unscaledDeltaTime`
- 되돌리기 어려운 조작(한 번 누르면 실패·진행이 바뀌는 것)은 `IHoldInteractable`로 길게 누르게
- 시스템 코드 수정이 필요하면 시스템 담당(양우성)에게 (PR 코멘트나 카톡)
